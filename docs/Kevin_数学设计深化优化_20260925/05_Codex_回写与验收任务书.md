## 2. 教具和课题采用一个场景数据源

每个场景至少有：

```ts
interface MathScene {
  sceneId: string;
  lessonId: string;
  story: { text: string; quantities: QuantityRef[] };
  expressionAST: RestrictedExpression;
  model: { type: string; quantityRefs: string[]; state: unknown };
  target: { prompt: string; responseSpecId: string };
  expected: { value: number | string; unit: string; explanation: string };
  taskMode: 'A_order_and_model' | 'B_equivalent_rewrite' | 'C_operation_law' | 'other';
  contentVersion: string;
}
```

`QuantityRef`定义唯一id、数值、单位、情境角色；物件展示只从这些数据渲染，不独立硬编码“20个”“70元”。AST只允许受限算术符号与括号，不允许把原题字符串`eval`。题目目标的AST验证比“最后数值碰巧相等”更严格。

## 3. 优先实现连续三课

**第一批：** B01→B02→B03。用户默认按课本顺序；组件可分别实现，但不能让B03在Kevin未理解B02时冒充已经基础通过。课堂是连续文章流，故事与对应模型需相邻。每个题卡必须能预测、操作、撤销、解释、独立测、保存恢复。

**第二批：** B04/B05与D01–D05基础诊断。默认完成基础闭环再显示E层主推荐，提升自由选、不解锁、不消耗已有学习证据。

**第三批：** E01与E03，A改变顺序/B保持值/C运算律三种任务显著标记；之后E02/E04/E05、O01/O02按实际理解逐步加入。

## 4. 必须自动验证的测试

- 5个核心表达式：`28−9+6=25`、`24÷6×2=8`、`(12+8)÷4=5`、`12+8÷4=14`（仅有12袋/8颗场景）、`20−(8−3)=20−8+3=15`，以及`70−(28−8)=50`。
- 反例：`20−8−3=9`，`48÷(6÷2)=16`不等于`48÷6÷2=4`；错误A/B模式切换后上一题的图和答案不得残留。
- B01输入第一步4时还有×2，不能算作整式完成。
- B02将4支和3盒直接加，提示单位不一致；保留原式不泄露最后正确答案。
- B03模型12颗+8颗与表达式要对应；第二情境明示12为袋数。
- E01主例和换数例切换时所有数值/单位/文字/目标/答案同源。
- 错题首答不可被最终答覆盖；自查屏不显示对错；已经曝光完整答案的原题不算独立迁移；同一taskInstanceId/eventId重试不重复记奖励。
- 重启前后恢复sceneId/草稿/帮助/积分；导出、预览导入、回滚后旧资产/宠物/历史无损；断网可用（依赖已经安装的本地项目）。
- 课堂可键盘操作，宠物不能覆盖题目，窄屏输入框/公式无裁切，错误提示不用颜色作为唯一信息。

## 5. 内容正确性门槛

实际首次投放的全部题目：家长或具名审核者核实题意是否独立、答案、单位、所有合理解、提示是否泄题、图与文字一致。开放解释只有参考要点而非唯一句式。后续每次内容摘要变化要使审核失效。自动测试报告要给“运行项、通过项、失败项、跳过项”，不能沿用旧次数。

## 6. 一次真正的Kevin试学记录

每课只观察：①他是否读懂题；②操作前先预测；③图和式能否一一对应；④无模型新题能否独立完成；⑤第一次错时能否自行查出；⑥提示用了哪级；⑦是否可自然结束。拿不到足够证据就记录“待判断”，不强行给高掌握率。
