## 0. 2026-09-25 深化审计后：本版生效的设计决议（优先于旧草案）

> **本文是对原设计稿的增补和定点纠偏，不宣称已修改网站源代码。** 如后文出现“建议先编码B01/B03”之类旧试制计划，按本节更精确的“**B01/B02/B03连续验证 → 补齐B04/B05并做基础诊断 → 再发布选学E/O**”执行。若奖励、题量与状态相冲突，按第0.6条及新增验收合同处理。

### 0.1 保留与改动边界

保留：教材原册/原章主入口，B/E/O/R、连续阅读课堂、现有宠物角色素材、本地运行、自由选课、知识和方法双入口共用同一ID、首答自查与独立迁移分离、1/3/7/21日回顾。

### 0.2 与Kevin最新目标对应的默认路径

```text
年级/册别 → 教材单元 → 基础B（概念、算理、练习、独立核验）
                                   ↘ 本章提升E（有边界的变式）
                                   ↘ 方法O（共享题卡、不另建重复课程）
                                   ↘ R间隔复习（原目标和提升分别记录）
```

- **默认推荐**：一个单元B的核心代表目标有证据后，才向Kevin呈现“本章提升”主推荐；E/O始终可以主动浏览，不灰锁、不强迫完成。三上混合运算B01→B02→B03→B04→B05→独立诊断是默认基础线；E01/E03/E02/E04/E05、O01/O02属自由选学，不能在菜单中看起来像必须全部做完才能进下章。
- 60课是内容节点，不等于60次必须完成的连续课。12题是题库，不是当堂负担。前8题备选/分次，P09–P12按到期投放；一轮一般3–5题，选学提升/思维同日合计最多一道。
- 先修提示只作建议；若Kevin实际会，可以短诊断后跳过重复首教；若他不懂，优先回到图或操作，不直接抛方程口诀。

### 0.3 对“交互”的验收定义

每个可发布交互至少有：`sceneId`、可见条件、可操作对象及其单位、合法/非法事件、操作前预测、同步变化、撤销、错误补问、撤除教具后的未曝光任务、保存恢复规则。缺任一项，不得在教案或地图标“已完成交互”。静态SVG/HTML审阅页只能标“图示或预览”，不计已经可互动。

当前附件的两份预览HTML分别展示48道课内提升题和部分思维图文，但没有提交控件、交互脚本和真实学习存档；其存在只能证明图文组织，不代表网站UI、判题和进度已上线。课程稿自报60课、720课内题及60张思维卡，项目运行仍另存旧课和少量试点课堂。**审阅人员不得把两种状态相加当作已上线课程数。**

### 0.4 三上混合运算的三类任务必须有三个不同的任务标签

| 模式 | 系统文字 | 核心不变量或变化 | 实例 | 禁止的误导 |
|---|---|---|---|---|
| A 按题意定顺序 | “这次要先把哪部分当作一包？” | **允许值改变**，因为题意或括号改变了 | `(12+8)÷4`与`12+8÷4` | 说“加括号都不改变答案” |
| B 等值添去括号 | “怎样改写，余额仍一样？” | 数值和原数量关系必须一致 | `20−(8−3)=20−8+3` | 只看结果偶然相等就算合法改写 |
| C 运算律与适用条件 | “为什么这样拆，全部数量没少也没多？” | 在本课约束的数域/运算范围内成立 | `7×(5+3)=7×5+7×3` | 错把乘法分配到除以和、减法任意重排 |

运算顺序是一套统一约定，真实情境是建模理由，分配律/等值改写必须用数量关系和步骤解释。教具不能以生活故事“证明”所有表达式的一般运算规则。

### 0.5 三个已确认的故事—数值—模型不一致，已在新版五课规格及审阅教案纠正

- B01：儿童故事是`28−9+6`，原交互初态却是`24÷6×2`；本版拆为显式两张场景卡，分别讲同级加减/同级乘除，切换时连物体和单位一起更新。
- B03：故事是18+12、每袋6，原交互却是12+8、每袋4；本版选12+8/4为主场景，18+12/6为独立换数。对照`12+8÷4`时12是**已装好的12袋**，不是12颗散珠；两种情境显式区分。
- E01：故事70、28、8，图示20、8、3；本版先用20/8/3操作，再用70/28/8迁移，切换时全部内容同步。

这不是“仅换数字”的美术问题：8岁孩子正在学习同一个符号对应同一个量，图与算式不一致会破坏等量替换与单位的信任。每次教学只能让他追踪明确的同一对象；需要第二个例子就明示第二张卡。

### 0.6 统一的证据与状态定义

- `introduced`：见过讲解；`operated`：操作过模型；`practice_pass`：练习正确；`core_provisional`：三道目标题达到客观标准，开放解释待成人确认；`core_confirmed`：独立作答且必要解释获得确认；`transfer_pending/passed`：新表示或情境的未曝光题；`retention_due/passed`：间隔回顾；`review_needed`：需要补回。状态不是单一“掌握度百分比”，可同时存在。
- **客观题不应因为成人没空点确认就卡住学习**：正确与错误可记录为客观结果，开放解释单独显示“待确认”；必要说明尚未确认时不声称四维掌握，孩子仍可自由进入其他课。
- 首答、检查后的答、帮助曝光、操作事件和奖励分开记；操作成功不是独立计算，提示后做对不是无帮助迁移，原题看过答案后只能订正。
- 旧课5分/题、结课20分与新规则冲突，**只有服务端统一并实际回归后**才能宣称日上限和去重已生效。不要在UI以未上线规则展示预计到账。

## 1. 请审核什么

希望审核者以小学数学教研、儿童交互和软件产品三个角度提出具体问题。优先判断课程内容是否准确、顺序是否合理、是否真正说明原因，而不是先评价画面是否漂亮。

请按“问题所在课程或章节 → 具体问题 → 为什么影响学习 → 可直接采用的修改方案”给出意见，区分必须改、建议改、可以试学后再定。对于数学错误请给出反例或正确解法；对于重复教学请指出两个具体位置。请不要把内容数量、页面完成或答题正确率直接等同于学习效果。

优先配套《Kevin三年级课程_完整教案审核稿.md》与《Kevin三年级_混合运算五课交互规格.md》。本稿附三年级索引及五课全文；原《Kevin三至六年级课程_完整教案审核稿.md》仍作合订备查，只更新三年级部分，四至六年级保持原稿。

重点审核：

1. 教材主线是否完整，混版衔接是否补对，必要知识是否遗漏或被提前当作先修。
2. 基础、提升与奥数的连接是否自然；是否只是把同一道题换数字重复放在不同年级。
3. 对 Kevin 的文字是否清楚，题目能否脱离上一道题独立理解。
4. “为什么”是否给出了数学原因；是否把生活情境编成未经考证的数学起源史。
5. 操作是否帮助理解，是否出现会拖拽但不会解释、会模仿但不会独立迁移。
6. 错题、复习、积分、成长是否有相互矛盾的规则。
7. 现有实现与目标方案间的缺口、迁移风险与合理的下一批范围。

## 2. 用户与已确认的边界

Kevin 目前三年级，使用人教版教材，主要在中国大陆的电脑上学习，每天约30–60分钟。家庭希望系统长期覆盖小学、初中、高中乃至更深入的数学；当前优先把三年级的内容、交互与记录做成可试学的完整路径；四至六年级保留已有稿，本轮不改。一二年级知识作为必要时的回补，初高中只保留扩展方向。

要求本地运行、学习进度容易导入导出、关闭前端窗口后服务继续运行。年级和课程可以自由选择，先修仅用于建议，不能把大量课程显示为灰色锁定。课程不按积分解锁。

首要教学目标是理解数学工具解决的需要、数量关系、规律与结构。基础知识要能向更深的思想延伸，奥数既可以从章节进入，也可以从方法索引进入；两种入口应引用同一份课与同一份学习证据。

保留用户认可的连续阅读课堂形式。宠物要使用用户认可的咚咚羊等已有角色素材；后续要求已取代旧方案中强推原创角色的方向。学习页宠物不遮挡文本。取消机械的“选择单位”步骤；题目必要的单位和量的意义仍须清楚。

当前奖励默认是**本网站内的积分与养成**。程序没有发放《蛋仔派对》真实皮肤、蛋币的接口，也没有与真实游戏账号连接。

## 4. 课程组织：课本为主线，思想贯穿其中

### 4.1 主入口与次入口

主要路径：

“选择年级与册别 → 查看实际教材章节 → 完成本章基础理解 → 选择相关提升 → 进入相应思想专题 → 回顾与迁移”。

方法工具箱提供第二个入口，例如点“逆向推理”可以看到三上错序运算、四年级数量关系、五年级方程、六年级求原量。索引只引用课程，不复制教案，不为同一次学习重复计分。

一二年级回补入口用于数数、数位、加减意义、表内乘除、厘米米、时分等先修。Kevin 已会的内容可直接跳过，不强制从数数开始走一遍。

### 4.2 四个层次不是四条互不相干的路线

| 标记 | 作用 | 完成证据 |
|---|---|---|
| B 基础/必要衔接 | 概念、算理、基本方法与教材主线 | 能解释并独立解决代表问题 |
| E 提升 | 改变条件、比较解法、推广规律、识别边界 | 能说明哪些条件不变、为何可迁移 |
| O 思想专题 | 将多个实例背后的方法显式整理 | 在不提示方法名称的新题中选用方法 |
| R 复习诊断 | 检查保持、跨表示和综合使用 | 间隔后独立作答；不足处定向回补 |

R不是把基础内容换个题目再讲一遍。B中也可有教材数学广角，是否选学取决于准备程度，不是看到B就必须当日通关。

### 4.3 教材混版的实质影响

| 年级 | 所供教材情况 | 对课程安排的影响 |
|---|---|---|
| 三年级 | 上册实际含观察物体、混合运算、毫米分米千米、称象、乘一位数、编码、线角、分数；下册含运动、一位数除法、周长面积、数据、年月日、小数 | 不能套常见旧版“三上时分秒、三下位置方向”的顺序 |
| 四年级 | 上册有“多位数乘两位数”“加法模型和乘法模型”等；下册为四则、运算律、小数、三角形等另一套编排 | 所供两册缺完整两位数除法；鸡兔在两册出现，主教案合并 |
| 五年级 | 上册实际“用字母表示数和数量关系”，并非旧版完整“简易方程”；下册有因数倍数、立体、分数等 | 必须补方程；观察和运动按已有经验深化，不能机械重教 |
| 六年级 | 上册已有数对、负数、折扣、利率及鸽巢；下册仍有负数、百分数（二）、比例、鸽巢和复习 | 合并重复首教；补比、扇形图；六下复习按诊断整合 |

这不是对所有人教版本的统一断言，只针对当前项目提供的八本PDF。更换教材版本后必须重新做差异映射。

### 4.4 混合运算的基础与提升怎样连起来

| 顺序 | 具体内容 | 学到什么程度、与下一层的联系 |
|---|---|---|
| B01→B02→B03 | 同级从左往右→先乘除后加减→括号优先 | 明确乘除彼此同级、加减彼此同级；保留中间结果，防漏第二步 |
| B04→B05 | 两步情境、分步式与综合式 | 说明括号包住哪个整体量；按问题找中间量，不靠关键词选符号 |
| 基础独立检查 | 5道保留的新题：计算、列括号、解释、逆过程验算 | 通过只记本章基础本次证据；不要求先完成任何E/O |
| E01→E03 | 等值去括号→反向等值添括号 | 净扣款/退款说明内部符号为什么变；不是只背口诀 |
| E02 | 连续除、除以积、除以商 | 对照48÷6÷2、48÷(6×2)、48÷(6÷2)，前两式4、后一式16 |
| E04 | 交换与结合的具体体验 | 加法、乘法分别操作；分两小次，不用字母通式当要求 |
| E05 | 乘法分配与合并 | 点阵完整覆盖；左右每部分都要乘；除以和的反例 |
| O01 / O02 | 错序逆推 / 整体命名替换 | 从执行过程倒推、把完整量暂当一张卡；可从本章或方法入口进入 |
| 三上乘法、三下除法 | 位值拆分、连乘连除、归一归总 | 相同思想迁移；没选E也能在基础课模型中重新建立必要关系 |

教材印刷19页（PDF25）的比较题和错序思考题已核对原扫描图。等值添括号与逆推有具体教材依据；新增运算律操作是主动拓展，不冒充教材已有完整的正式运算律单元。三年级只用具体数和实物，四下再一般化；四至六年级本轮不修改。

三种括号任务分别命名：**A“按题意添括号，可以改变值”；B“等值添去括号，值必须不变”；C“借运算律改写，先说明成立依据”。** 20−(8−3)=15，等值去括号为20−8+3；20−8−3=9是另一个过程。7×(5+3)可拆为7×5+7×3，不能漏掉后一项的×7。统一顺序是约定，情境用于建模，规律成立另由数量关系说明。

### 4.6 每次最后一道思维题：提升与奥数的入口

已收到《Kevin_数学20天专项练习_指定页码版》，通读26页并重新验算20天60道思维题的参考答案。保留原34张思维题卡，增加20张对应暑假方法的改写/变式卡、6张长度连接卡，共60张。按教材基础挂靠，不把20天重新变成一套孤立课表；见《Kevin三年级_暑假提升题对照与修订说明.md》。思维题全文与15幅原创数学图已收入《Kevin三年级_提升与奥数思维题.md》及完整教案。

任务包含前置课、从基础延伸的理由、完整题干、两级提示、答案、推理步骤、反例/适用条件与评价证据。例如：错序为什么总多10；数位看错如何影响乘积；8球两次称出重球；余数条件找全11或23；棋盘染色说明拼不成；周期日期的配对补偿；和差问题为何只需转移差的一半。既有具体操作，也有有序枚举、逆向、等量替换、不变量、抽屉、和差与有限方案比较。

长度主线具体分为：量一根 → 两块搭接去重 → 多处接头计数 → 反求每处重叠 → 链环端部投影 → 缺条件与三重重叠反例。4厘米必须说明是外长，5毫米必须说明测的是哪一段；先读图、标端点、说重叠，再算。

图文显示约定：题干与标注图同时出现，条件不埋在答案或悬浮提示中。静态SVG提供完整文字备份，未看图也能按坐标/标注重建关系；禁止测屏幕取长度。初始层给原始条件，提示层才揭示重复次数，解答层才显示完整算式。未来拖动木板时，模型要明确约束直线搭接、端点和是否允许三重覆盖；切换模型条件后不能继续沿用旧公式。图文样张HTML已可离线查看，拖动、判分、学习记录仍待网站实现。

质量门槛：必须比基础题多一项实质思考（找隐藏关系、判断条件、构造反例、有序穷举、证明最优或跨模型迁移），不是大数多步计算就叫提升。每张记录挂靠基础、思考证据和适用边界；六条方法连接串起相关卡片，方法工具箱共享题ID与进度。单位已在题干和输入框说明，不再添加选单位步骤。

每次最多一题，8–12分钟可跨日继续。先独立尝试、按需逐级提示；不作为基础门槛，不强求当日做完，提示后不计独立证明。题目问“所有可能”时给出完整有限解集；问“保证/不可能/最少”时必须说明为什么，不能拿一次试成功或试失败代替理由。方法工具箱按同taskId引用本题，章内与方法入口不重复发奖。

### 4.7 全部单元都必须满足的提升标准（2026-09-25）

链环与重叠只是例子，这套要求同时应用于三年级17个教材入口、60课。详见《Kevin三年级_全单元质量复查与改写记录.md》和权威数据grade-3-quality-map.json。已逐课核查真实任务、原因说明、P05–P08及关联思维卡：48课各替换一道偏浅或重复的备选题，12课保留已有合格反例、等值对照或余数边界。每课extensionContract指向实际题ID与思考证据，不只写“以后补提升”。

统一链条为：**现实需要 → 课本基础模型 → 改变一个重要条件或所求量 → 解释关系为什么成立 → 在新条件下验证或反驳。** 基础保留清晰、短小的必要练习；提升不能仅凭题目长、数字大、步骤多来定义。允许未知量、操作和试验，三年级不强制字母方程或形式化证明。

- 数与运算：位值、进位与0是保持数量关系的记录；提升研究误读怎样改变结果、从进位倒推、预算上下界，不能只重复竖式。
- 测量与图形：先明确测的是哪条线或哪片覆盖；提升研究接头、靠墙、剪拼、遮挡、旋转和折痕的条件，不是一律套周长/面积。
- 分数与小数：先明确整体和计数单位；提升研究改变整体、重复部分、几份反推整体、位值误读和有约束的最大数。
- 统计与日期：先明确记录范围和计数口径；提升要求构造符合分组的不同数据、检验结论证据、找周期、补齐时间线里的等待。
- 综合与数学思想：比较可行方案、列全可能、解释最优或不可能；章内与方法工具箱共享taskId和conceptId，不复制一套重复课程。

48道改写题都在备选位置，原来的最低基础过关题不变；每题有两级具体提示。新加11幅课内图，连同15幅思维图共26幅。图按作用分为题面条件图和提示图；例如共线三点的两种位置必须让孩子先尝试构造，提示后才能展开。所有图有文字备份，离线HTML嵌入SVG，无需外网。

**掌握记录必须分层。** 基础P09–P12的分日回顾通过，不意味着本次新增提升也已掌握。提升另记独立尝试、帮助级别、解释和新条件迁移；看过完整解答的原题只能作订正。暂时没有对应独立迁移证据，就记录待迁移，不自动升级徽章。日常一课的备选提升与思维卡合计最多选一道，允许跳过或跨日。

## 5. 一节课应该怎样展开

采用一条连续阅读线，每个图与操作紧贴正在解释的句子：

1. 一句可理解的本质结论或学习问题。
2. 条件完整、贴近经验的现实任务。
3. 实物、图形或表格模型；所有符号说明代表什么。
4. 操作、观察与解释“为什么”。
5. 完整例题和一个边界/反例。
6. 分层练习：巩固、变式、迁移、挑战、间隔回顾。
7. Kevin用自己的话复述，并说明什么证据还不足。

固定结构不等于每课机械使用相同话术。有的课需要先操作再给名称；有的课已具备先修，可先读关系再验证。所有操作必须留下可解释的数学变化。

### 5.1 教案字段与发布契约

三年级现有JSON包含原有讲解、例题、12题、来源、稳定ID及回顾日程，并补上：

- concepts：稳定conceptId、首次/复习/深化/迁移、具体范围。
- learningRole/teachingContract：教材核心或选学、3道最低代表题、其他备选、最低证据、暂停与回补、分次安排。
- interaction：初始状态→动作→可观察变化→追问→预期解释→错误反馈→撤除教具后的完整独立题；五课另有状态机。implementationStatus明确为specified_not_implemented。
- selfCheck：firstAnswer、checkActions、finalAnswer、helpLevel、adultDecision分开。
- practice.audit：unreviewed / auto_checked / human_checked / needs_revision；另有AI编辑复核的身份和内容摘要。auto_checked仅自动筛查，不能显示为“教师审定”。
- scoring：本题参考答案、理由证据、等价表达及成人确认出口；当前均未编译为运行时评分器。

发布适配器还要生成受限的responseSpec：整数/有理数/余数对/表达式树/动作状态/开放解释/复合任务。混合题拆为数值与解释两项证据：数值匹配不等于解释成立。单位固定随输入显示，不增加机械单位选择；分袋题用“人数”和“余袋”两个有标签的输入，不能把余1袋误记余1张。

表达式任务必须同时验证数值与题目指定结构。例如“等值去括号”不能只接受输入15，须给无括号等值表达式；括号插入任务限制原数字顺序与允许改变的符号；任意等于15的算式不算达成本题目标。多解题保存接受规则和反例，不能只接受参考答案一个字符串。自由解释暂存待成人确认，不调用不透明AI接口来强行判满分。

内容版本、任务实例、题目快照与规范化判题版本绑定；修改题干答案后应使旧内容摘要的审核失效，旧答题记录仍保留。发布版本不可在构建时静默覆盖。

### 5.2 练习质量的约束

每课现有8道当堂备选题和4道分日回顾题。外审仍需判断是否有表面变式、实质重复：

| 任务 | 真正的差异 | 不能冒充差异的情况 |
|---|---|---|
| 计算 | 算式结构、数域、边界条件改变 | 只把12换成15 |
| 解释 | 说明单位、整体、等号、每一步含义 | 点击“我理解了” |
| 变式 | 变一个条件，判断原方法还成立吗 | 重复套同一模板 |
| 迁移 | 情境、表示、未知量位置或建模路线改变 | 保留原图并提示同一方法名 |
| 挑战 | 需要枚举、反例、极端、逆向或证明 | 仅增加大数字和步骤 |
| 回顾 | 间隔后独立解决另一实例 | 当日照抄刚显示的答案 |

自由复述先保存原话；未能可靠判断时标记“待确认”，不能为了给动画奖励而自动判对。图题需要提供实际图或完整可重建描述，不能只写“看图”。

## 6. 网站交互设计

### 6.1 当前与目标的信息架构

当前代码有：今天、探险地图、方法工具箱、复习站、蛋仔家园、错题修复、家长中心。文章课堂已经融入正常课程入口，没有要求单独进入“样板课专区”。

下一版地图应优先呈现“年级—上/下册—教材章节—B/E/O/R”，原有知识岛和八领域作为辅助标签。今天页面推荐一个可解释的小目标；不能把“看完一节”包装成“掌握全部目标”。

学习入口可自由选择。先修不足时提示“这节会用到什么”和两三道短诊断，允许继续或跳到回补。未写好内容须明确标“准备中”，不能用灰色造成“必须刷低年级才能解锁”的误会。

### 6.2 课堂与宠物的空间关系

主内容居中，故事、模型、解释连续排列。宠物在左侧独立窄列，桌面历史版本采用104px、小屏64px的空间规则。气泡不能覆盖正文；长对话可收起，鼠标点击触发短回应。

“真实问题”应直接写清是谁、有什么、做什么、问什么。避免只写抽象的“铺砖和围栏是不是一回事”再让孩子猜教师意图。互动题的提问和选项必须对应同一个问题。

练习不强制选择单位。需要输入时固定显示单位，涉及周长面积的区分则通过实际含义提问，而不是让孩子额外点一个下拉框。

成功反馈先说明“你发现了什么关系”，再显示小动画和本次真实到账分数；动画可跳过、可静音，不阻塞下一步。错误反馈指出可以检查的具体步骤，不把孩子标成“不认真”。

### 6.3 教具的目的与技术取舍

| 内容 | 推荐表现 | 数学检查点 |
|---|---|---|
| 数量与位值 | 点阵、十格、捆棒、位值表 | 移动位置不改数量；换单位要保总量 |
| 四则与括号 | 可分组条形、步骤树、表达式同步 | 每个括号圈的是哪个完整数量 |
| 分数 | 同一整体的纸带、分组、数线 | 整体、等分、份数分开；不能只改标签 |
| 运算律与方程 | 阵列切分、天平、整体替换 | 两边/两部分守恒；替换范围明确 |
| 周长面积 | 描外边与铺内部两种操作 | 边界和内部不同；接缝减两次 |
| 空间几何 | 可旋转的实物模型、展开图、截面 | 视角不等于物体变化；未见处存在歧义 |
| 数据 | 可读的表、图例、刻度与筛选 | 图与原始数据一致；选择合适图表 |
| 思想专题 | 有序表、树、状态记录、反例框 | 能解释不重不漏或规律的适用条件 |

优先用HTML/SVG和可检验的数据模型，保持文字可访问。必要时用Canvas/WebGL表现复杂立体，但不因“沉浸”把全部内容改成3D场景。当前项目并未完整实现上表所有教具，也未引入统一3D引擎。



### 6.4 可交付的页面与视觉规格（新增；不是“更漂亮”四个字）

| 页面 | 最重要的一屏 | 第二层内容 | 不允许出现 |
|---|---|---|---|
| 今天 | 今日推荐1课+到期回顾≤3题+可选一题提升 | 完成记录与继续上次位置 | 8个平级大按钮争注意力 |

```text
[开始1道无模型新题]  [保存并退出]
```

**状态稿须至少覆盖：** 初入、读题预测、合法操作中、单位冲突、顺序错误、自查不泄露对错、答对/错后反馈、提示揭示、撤除模型独立测、断开/恢复、窄屏、键盘操作。每种状态要有文字/模型/事件/存储字段对照，不能只给一个正常态静态图。

### 6.5 交互分级与撤除帮助

| 等级 | 形式 | 适用目标 | 可记录什么 |
|---|---|---|---|

## 7. 错题、掌握与复习

### 7.1 先保存事实，再推断错因

保存题目快照、首次答案、后续答案、提示和解答使用、目标、时间、相关模型状态。先记录“分母也相加了”这类可观察事实，再标“可能未理解分数单位”，不能只凭一个错误答案作确定诊断。

错题入口应能按章节、目标、常见结构、复发次数、到期时间查看。打开一类错误应看到代表题、可能原因、一次有区分力的补问、回补讲解、新变式和复习时间。

当前代码：旧题主要按课程归组，新题可按目标归组；原错误和时间保存。尚无完整的过程补问、家长纠正错因、目标级修复路线。

### 7.2 四类证据分开

“独立求解”“说明理由”“新情境迁移”“间隔后保持”分别记录。只做对原题不能代表迁移，看完讲解不能代表独立，复习站点过一次不能代表长期保持。

当前程序保存对错、帮助、事件和部分目标信息；还没有完整四维掌握模型。同一天重试不累计为多个保持样本。界面不能把这些已有记录统一包装为百分百掌握。

### 7.3 复习时间

目标默认是首次核心学习后的第1、3、7、21天；这是可调的产品起点，不宣称适合所有孩子的唯一最佳间隔。

当前实现已将复习锚定首次核心完成日期。逾期通过后选择未来锚点；有错误或帮助时安排次日再测；同一家庭日只生成一次保持记录。当前代码在所有锚点之后再约28天安排回顾。尚未完成新任务实例派发、目标级难度调整及完整前置修复。

日期以UTC+8家庭日处理，文件时间保存ISO字符串。以后允许更换时区时，应迁移家庭日规则，不可依客户端随意改时钟刷奖励。



### 7.4 针对Kevin口算失误的真实“自查环节”

混合运算输入时，不能用“认真一点”代替可执行流程：显示并记录**读完整式→选第一步→算中间量→完成第二步→查符号→再算一次→最终确认**。对于9÷3−2、9×9+5、7×8+18这类已出现的失误，首答后先问“你还有没有没处理的运算符号？”而不是先告诉哪个数错了。只有最终提交才反馈对错。

例如首答 `9÷3−2=6`，在没有直接给答案的情况下可以问：“9÷3之后，原式还剩什么？”记录Kevin是否能自行答出“3−2”。区分补问是定位可能错因，不是一次错误就给他贴“不会运算顺序”的标签。

### 7.5 首答、自查、评分与奖励必须原子且可重试

一次作答的稳定键为`contentVersion + taskId + taskInstanceId + userId`；`eventId`由客户端为**同一次提交**生成并持久保存，在网络重试时复用，不能每次点重试再发新的ID。服务端先校验任务实例、响应格式与版本，再事务内写入首答/最终答、帮助证据、掌握事件、奖励账本，最后返回真实到账；拒绝重复入账。

`responseSpec`须表明回答类型（数字、带单位数量、过程选择、结构改写、有限多解、图形构造、自由解释）。数学表达式必须解析为受限AST，不能只比最终数值：`20−(8−3)`改写成`20−8+3`属于本课目标，任意凑出15的表达式不属于；`(12+8)÷4`若任务要求**按题意加括号**，不能靠任意改数字得到5。

提示/完整解答记录先落盘再显示；后续原题订正不算未帮助独立迁移。迁移题与回顾题均需未曝光题实例，耗尽时标成人补题而不是重复原题制造掌握证据。新增奖励政策只在运行端通过迁移与账本回归后生效。

## 8. 积分与蛋仔养成

### 8.1 目标规则

星点可以买物品；伙伴成长反映共同学习；知识证据用于教学。三者分开，不以花钱多少决定数学掌握，不以做题越快给予倍数奖励。

目标规则为有效任务基础2分，独立迁移/解释可有预先定义的额外项；任务奖励每日最多30，完成约定学习与检查计划每日另5。答案展示后的原题不给新奖励；答错不倒扣已有积分；同题订正不重复发两次分。

日常照料应可免费进行，伙伴不会因停学而饥饿惩罚或退化。商店明码、可预览、直接兑换；无随机抽取和倒计时。商品不解锁教学功能。

### 8.2 实际代码与目标存在差异

- 新课堂已有2分基础、部分额外分及30+5上限；旧课仍有5分/题、20分结课的另一套规则。**全站统一35分日上限尚未实现。**
- 新课堂每日首次核心组完成会让已拥有伙伴各增加成长；旧课和喂食仍有其他成长入口。不能声称已经统一为“每个有效学习日全体仅+10”。
- 购买有余额、库存和请求重复检查；尚无完整报价版本、预览确认、误购撤销及家长纠错流程。
- 目前可切换、喂食、互动、接星星、布置和领取学习礼物，保存成长、亲密和回忆；尚无完整免费自选首只、命名、孵化、四阶段独立外形。
- 角色使用本地图片与少量本地语音；并非每只都具备足量台词。用户要求的“咚咚羊等已有素材”优先于旧设计中原创形象的提案。

实际配置例：咚咚羊0分、蜜蜂DongDong160分、鸭鸭DongDong280分；普通食物10–25分、围巾60分。旧设计中120/180等定价属于目标草案，不是当前配置。正式调价要保留已有物品和账目，不能悄悄重置资产。

### 8.3 需要试学评估的体验

观察 Kevin 是否因为想理解题目而继续，还是只追逐重复刷分；能否在完成一次学习后自然结束；每几次有效学习能获得一个看得见的变化。成长应有新动作、对话和共同回忆，不仅是数字增加。数学提示与复习入口始终免费。

### 9.3 数据持久化与提交路径

SQLite不是为每个实体建了关系表。当前只有单行progress表，payload保存完整JSON进度，启用WAL与FULL同步。写操作在BEGIN IMMEDIATE事务中读、修改、更新，失败ROLLBACK。适合当前单用户本地规模，长期题量大后需评估事件归档、导出大小和性能。

Progress包含profile、settings、旧attempts/lessons/reviews、wallet与ledger、pets、inventory，以及studio下的reading、sessions、notes、events、entitlements、daily、review。

新练习流程：

1. 创建或恢复会话，保存本次题目快照、版本与taskIds。
2. 草稿保存答案与当前题号。前端约650ms防抖，串行保存，显示待保存/已保存/失败重试。
3. 提交携带sessionId、revision、taskId、answer、eventId。
4. 服务端检查版本与会话，受限判题后记录事件，更新进度、账目和复习。
5. 返回判定、实际到账、revision和进度；前端再播放反馈。

服务端revision检查避免旧页面覆盖新数据。已有重复事件回执和奖励权益去重；前端响应丢失后复用同一eventId的全路径仍不完整，不能将“服务端有幂等逻辑”表述成所有网络重试已验收。

### G3-U02-B01 一串加减或乘除，按什么顺序算

**定位：** B；建议35分钟。来源G3-upper：印刷6–7 / PDF 12–13。
原创教案；页码锚定相关教材内容，不表示本教案题目出自教材。

**先修：**表内乘除、两步加减。
**关联课程：**依已有能力直接进入

**目标：**能识别同一级运算，并从左往右计算。

**真实问题：**车上有28人，先下车9人，再上车6人；想在一行里记录变化。

**为什么：**一串符号需要大家用同一种方法读取。数学约定：没有括号时，加减同级、乘除同级，同级从左往右算。这是统一的书写与读取约定，不是从某一个故事证明出来的规律。故事另外帮助我们检查式子是否表示了题意。

**模型操作：**把每一步人数写在连续三张卡片上；另用24个棋子先分6组再把每组取2倍。

**讲解：**

1. 只有加减时，从左到右算：28−9+6先得19，再算19+6得25。
2. 只有乘除时也从左到右算：24÷6×2先得4，再算4×2得8；不是乘法永远先算。
3. 每次只把刚算的部分换成结果，把其余数字和符号原样抄下。24÷6×2=4×2=8；不能在等号左边只写24÷6，却在右边接上4×2，因为两边不相等。

### G3-U02-B02 没有括号时，先乘除，再加减

**定位：** B；建议35分钟。来源G3-upper：印刷7–8 / PDF 13–14。

**关联课程：**G3-U02-B01

**目标：**会按先乘除后加减计算，并区分运算顺序约定与情境中列式的理由。

**真实问题：**有3盒彩笔，每盒6支，另有4支散装彩笔，一共有几支？

**为什么：**为使同一算式有一致的读法，数学约定无括号时先乘除后加减。彩笔故事中先求3盒共有多少支，是这个情境的数量关系；它解释为什么列4+3×6，但不是证明所有算式顺序的依据。

**模型操作：**画3个框，每框6点，框外4点；框内总数对应3×6。

**讲解：**

1. 先说明约定：有乘除又有加减，先算乘除；乘和除同级，加和减同级。
2. 3盒每盒6支，先得到18支，再和散装4支合并；3是盒数，4是支数，不能先把3与4相加当作盒数。
3. 4+3×6=4+18=22。先写下未算的4+，防止算出18就停。
4. 只有算式而没有故事时，同样按约定计算；先读符号和括号，再决定第一步。

### G3-U02-E01 去掉括号，怎样仍表示同一笔钱

**定位：** E；建议35分钟。来源G3-upper：印刷12–19 / PDF 18–25。
原创教案；页码锚定相关教材内容，不表示本教案题目出自教材。本课作相关内容的提升，超出教材直接要求部分见讲解边界。

**关联课程：**G3-U02-B04

**目标：**用扣款和退款解释减去一个和、减去一个差及加上一个差的等值去括号；只用中间量非负的具体数。

**真实问题：**有70元，支付一件标价28元、优惠8元的物品。怎么写实付后剩余的钱？

**为什么：**减去的是实际花的钱28−8；若先扣28，就要把没有花掉的8加回来。

**模型操作：**把70元余额条分成实付20与余款50；对照“先扣28再退8”。

**讲解：**

1. 有20元，要支付标价8元、优惠3元的物品，实付8−3=5元，余额20−5=15元。
2. 也可以先扣8元再退3元：20−8+3=15。退回的3元应增加余额；20−8−3表示又扣3元，只有9元，是另一件事。
3. 若买两件分别8元和3元的物品，则20−(8+3)=20−8−3=9，两筆都要扣。
4. 若原有20元，新得到8元又从新得的钱中用掉3元，则20+(8−3)=20+8−3=25。括号前的加或减决定整个净数量是加入还是扣除。
5. 本课先从有括号改成无括号；反过来如何添括号保持值，另到E03。这里不用字母公式，也不把负数计算当作先修。
