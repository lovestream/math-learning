## 五、其他值得修的具体细节

### P2-01：「当前实验」与「实际完成操作」的证据要精确

\`shared/classroom-expression.mjs\` 中：

\`\`\`js
const active=state.actions?.length||state.sceneId||state.labVersion||state.handsOnVersion||state.stateKind;
\`\`\`

这里只要存在 \`sceneId\` 或版本/状态字段，就可能展示「刚才我做的实验」，但不代表孩子已真正执行数学动作。**这属于状态命名和操作证据风险，不等于数学算式错误。**

建议：
- 只有可靠的交互事件或已变化的状态才展示「刚才我改过的条件」；
- 如果只是选中场景或默认初态，标题改成「当前实验条件」；
- 仍可展示空白算式模板，避免暗示孩子完成了操作；
- 独立掌握和积分继续只由正式练习/复习判定。

### P2-02：六步走不是「六步走完=理解」

\`ChildClassroom.tsx\` 允许自由点击六个步骤，这是友好的。测试也可在未操作时直接到「说出发现」「写成数学」「自己验证」，不应据此记录概念已掌握。保持功能不设置死锁，后台显示 \`浏览/操作/独立练习\` 三种证据；不要因页面步号升级称号/积分。

### P2-03：对一节课的「实际操作 + 熟题巩固 + 未见迁移」要准确命名

第6屏已写「巩固练习」并明示含熟题，这是改善。Codex应在最终台账把同故事题与变化情境题分开，避免把练习首题原样复述当作「未见迁移」。不需要重写既有849题；优先更新学习报告和适用标签。

### P2-04：数学内容测试覆盖要逐题清点，不等于每题都需人工逐字改写

用户要的是扎实完成三年级，而不是自己承担849题逐题审核。要求Codex先**自动遍历849题**：
- 数值题：有明确算法的用独立数学oracle检验；
- 分数与单位：分数等值、单位换算、范围约束；
- 文本解释题：检查题目、答案、理由、对应教材概念一致，不能自动宣称数学推理正确；
- 选择题：禁止「正确选项措辞明显更像答案」；
- 每章至少抽查核心、迁移、挑战、复习四类；
- 对异常题集中人工逐题复审，最终输出 \`machineCheckedCount\`、\`humanCheckedCount\`、\`unverifiedCount\`、失败题清单。

无论此前「内容检查通过」，**不应将其等同于849道题的人类数学审校通过**。

### P2-05：只用电脑，测试口径和布局也要调整

- 不再要求实体iPad；不拿iPad未测作为软件交付阻断项。
- 电脑主尺寸：1366×768、1440×900、1920×1080；检查桌面第3屏教具是否合理占屏、输入是否能见到、上一步/下一步是否固定不遮挡。

- 触摸设备布局可以保留已有适配，不再要求特别的设备验收截图。
- 电脑键盘操作、Esc/Tab焦点、鼠标拖动与失焦保存仍应回归。
