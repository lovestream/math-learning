## 一、明确结论：当前难懂的原因是什么

1. **“真实链环”和“测量的长度”不在同一个视觉系统里。** 主实验区画了相扣的椭圆环，下面又是每环单独一张“40毫米色带卡”；孩子需要自己把链环、色带和放大框合成一个概念。木板课成功的地方，恰恰是**看着同一个物体移动，重叠部分就在原位**。
2. **40毫米标注脱离了物体。** 当前`ChainExperiment.tsx`在整个SVG上方只给第一环画外长尺寸线，下面`ChainLengthStrip`又为每环另画一个40毫米横条。儿童难以知道这是“每个环从最左外缘到最右外缘”而不是内孔、金属长度或接好后的新增长度。
3. **“5毫米+5毫米”仍是第二张抽象图。** `ChainJointFigure`里“前环外长范围/后环外长范围”的矩形与真实环的端部对应弱；两个5毫米挤在小范围内，放大图说明需要读数行文字，不能像木板盖住的那段一样直接看见。
4. **界面过密，主次倒置。** 1440截图中，主实验工作台后面接两列外长卡、接头文字、放大图、两种算式、旁边发现单；结果一个数学事实被四处解释。即使卡片等宽，也只解决了程序绘图断言，没有解决儿童理解。
5. **模型切换没有真正共用一套“长度账”。** 两种方法目前由`ChainLengthStrip`的`subtract`分支切换；孩子看到的是两种说明版式，而不是在**同一条已经连好的链**上改看“新增部分”或“重复部分”。
6. **外观不应暗示环不等长。** 主视图的`Ring`虽然横向`width=length*scale`相同，却交替使用`height=64/100`及不同纵向位置；下方再把新增加的30毫米分割成独立颜色条，容易误读成“新环比第一环短”。完整环永远是40毫米；30毫米仅是**安装后的轴向净增量**。

### 必须修正旧审查意见中的两点

- **不要把“长方形色带”换成未经数学验证的精美3D链条就算完成。** 真实感仅用于辨认对象；所有端点和相扣结构必须与`chainMeasure`的轴向投影精确一致。不能凭美工任意旋转、透视、错层后仍硬写`5+5=10`。
- “已经计入的10毫米”是**把各环外长相加时重复计数的轴向长度**，不意味着铁环材质真的被覆盖、缩短、剪掉或消失。用语推荐“**这一段已算过，本次不再加**”，不要把物理金属和长度账本混为一谈。

## 二、唯一推荐的主画面：一条链 + 一条共轴长度尺 + 接头原位放大

**不要保留四张2×2独立长度卡作为主教学图。** 一屏以**同一条已经接好的链**为唯一研究对象，宽屏版建议：

```text
┌────────────────── 一次只研究这一条链 ──────────────────┐
│ [同一尺寸的链环①]扣[环②]扣[环③]扣[环④]                 │
│       │←── 第1环 40 mm ──→│                           │
│                ┌─ 选中接头②：放大查看 ─┐                │
│                │ 前环右端5 │ 后环左端5 │  ←共同的10mm    │
│                └───────────────────────┘                │
│  长度尺 0 ────40───70───100───130 mm                  │
│          [第1环40][增加30][增加30][增加30]            │
│              ↑     ↑选中后高亮新增的30mm              │
│                                                       │
│ [接上一个环] [撤回]   当前：3个环 · 2个接头            │
│ 提问：新环原本也长40mm，为什么总长只多30mm？             │
└───────────────────────────────────────────────────────┘
```

这是**结构说明草图而非严格几何比例图**。Codex必须让坐标、端点标注、接头框、长度尺共用**同一毫米→SVG x轴映射**；实际数值顺序由当前放置环数变化，不能只凭草图硬编码。

### 2.1 上层真实环：简洁但确实“扣在一起”

- 每个环使用**相同外长、相同粗细、相同外观比例**的椭圆/跑道形闭合环；交替两色帮助分清相邻环，不要通过缩短/拉长环或交替40%-100%高度展示前后。
- 允许前后交错的遮挡关系，但交错不能掩盖测量端点。若SVG透视造成轴向坐标不准确，请采用**明确的二维俯视结构示意**，而非强行3D；链环的交叉关系通过局部前后遮挡表示。
- **在第1个可见环的两端外缘直接画两条竖直引导线**，从环的左最外点和右最外点落到尺寸线，并以双向括号标`完整外长40毫米`。可以点任意环后，同样在被点的环上展示40毫米，不允许尺寸线悬空。
- 孩子眼里最醒目的东西只有：链、一个正在变化的接头、端到端测量、一个问题。去掉“测量实验室/底层几何条件/所有公式”大块同步堆叠。

### 2.2 同轴长度尺：像木板重叠一样看得见“只多了哪里”

- 共享的毫米坐标：`ring[i].left = i * (L - 2t)`；`ring[i].right = left + L`。每个完整环都是`L=40`，每个连接区宽`2t=10`。这些区间直接来自`chainMeasure()`，不能独立自绘另一套数。
- 接上第2个环时，原链右外端固定以明显竖线标为“**原来在这里 40**”；新链右外端移到70，并高亮**新伸出去的40→70区间，即30毫米**。
- 接第3个环：原来70、新的100；接第4个环：原来100、新的130。**绿色只标新增长度30**；接头共享区**橙色10**；灰色表示已经计入的长度。环实体不变短，颜色只变化“哪些轴向区间已计入”。
- 每步显示一个小而清楚的对比：`新环外长40 = 已计入10 + 真正新增30`。这不是将环“剪成10和30”，而是对完整环外长的**计量区间分解**。
- 尽量避免铺满背景网格；图能看清比“工程测绘仪式感”重要。

### 2.3 接头局部放大：保留当前较清晰的预测页参照，但用得更准确

保留可复用的`ChainJointFigure`思路和用户认为较清楚的“先猜一猜”的接头位置，但**必须纠正位置、对象归属与标注**：

- 放大镜直接由主链某一接头位置以**同色虚线框和连接线**引出，默认先选**第1处接头**，而不是主链选第3处但下方所有条卡一起在讲另一处。
- 使用`chainJointGeometry(t)`为唯一数学坐标：共同区间`[0,2t]`；**前环的右外缘位于该区间最右侧`2t`**，它的实体右端金属是`[t,2t]`；**后环的左外缘位于最左侧`0`**，实体左端金属是`[0,t]`。
- 上下两行**同一水平比例**：前环的完整外长延伸到右边界，后环从左边界开始向右延伸；两个金属端部沿轴向在中间`t`处相遇；它们并非空间里硬粘成一整段钢条。
- 放大图上**直接用两支尺寸括号**指向前环右端金属和后环左端金属，分别标`5毫米`；共同虚线框下标`同一处接头，长度账上重叠10毫米`。不要只写“前环范围/后环范围”两条抽象色带。
- 用从主环到放大镜的**相同颜色**保持身份映射，并标`环①的右端`、`环②的左端`。显示位置时可点主图切换哪处接头，不要复制多份不同样式的放大图。


## 二点五、双环最高优先验收方案（用户最新要求，先于后续四环开发）

### 2.5.1 先确定唯一的数学几何：不能让两种算法对应不同的图

在本题规定的**理想化拉直轴向外长模型**中，先只显示两个**大小完全相同、未缩短、未剪开**的环。主图横轴共享一套毫米坐标（SVG只做等比例转换），用颜色区分环①与环②：

| 要展示的量 | 对应的实际测量区间（毫米） | 界面怎么标 |
|---|---|---|
| **① 第一个环完整外长40** | 环①左外缘`x=0` → 右外缘`x=40` | **第1层尺寸线**直接引到第1个实体环左右最外端，标“环①完整40毫米” |
| **② 第二个环完整外长40** | 相扣位置的环②左外缘`x=30` → 右外缘`x=70` | **独立的第2层尺寸线**直接引到第2个实体环两外缘，标“环②完整也是40毫米”，绝不能标成30 |
| **③ 这一处接头共同的10** | 原链轴向共同区间`x=30` → `x=40` | 原位橙色半透明框，放大时上方归于**后环左端金属`[30,35]`=5**、下方归于**前环右端金属`[35,40]`=5**；方向及前后环归属必须正确。 |
| **④ 接上环②后真正多出的30** | 原末端`x=40` → 新末端`x=70` | 下方绿色横向箭头贴紧同轴尺，标“本次净增加30毫米”，不另外画短的“环②”。 |

**这四个标注要在同一幅两个环的画面里同时成立，孩子一眼能够分别指出。** 尺寸线分上下错层，`[30,40]`同时是“环②的左边10”和“环①已占据过的区间”，而不是声称两个完整物体各少了10毫米。

渲染模型只接受同一来源的数据：

```text
L = 40mm, t = 5mm, o = 2*t = 10mm
环①：start1 = 0; end1 = 40
环②：start2 = 40 - o = 30; end2 = start2 + L = 70
接头共同区间：[30, 40]
环②的完整40：[30, 70]
环②的有效新增30：[40, 70]
相扣总长：70
```

由`shared/length-model.mjs::chainMeasure(L,t,2)`的`starts`、`overlapMm`、`extensions`、`totalMm`派生，不允许在React里再写一套手算位置。

### 2.5.2 同一个双环样板要支持两个观察视角

**视角A（默认，逐个新增）｜不移动环，先读清四个量。**

初始画面先出现环①，外缘引导线明确40mm。点击“接上第二环”后，一整只40mm的环②平移进入相扣位置（终点`[30,70]`），**不是从40缩成30**。接好后依次以很短的视觉强调显示：

1. 环①完整40mm（标在环①实际两外缘上）；
2. 环②完整40mm（标在环②实际两外缘上，说明“第二个环并没变短”）；
3. 共同区间30～40用橙色框圈出，共10mm，点放大看到“环①右端5＋环②左端5”；
4. 原链最右端`40`保持一条可见的刻度线，新最右端`70`出现绿色箭头`40→70`：**只增加30mm**；
5. 最后才显示`40 + (40 - 5 - 5) = 70`，并给Kevin一个简短问题：“第二环还是40毫米，为什么只多了30毫米？”

**视角B（先相加、再减重叠）｜用户新提出的“拉开比较”。**

**核心是拖动环②的完整轮廓位置，而不是拖动一条30mm的色带。** 第二环在`x=30`相扣时，两环端到端总长70mm；孩子沿横轴右拖**至刚好不重叠、两环首尾相邻**（第二环区间`[40,80]`）：

| 展示状态 | 环① | 环②完整外长 | 第二环左端 | 整体端到端长度 | 强调给孩子看 |
|---|---|---|---:|---:|---|
| 相扣（拖动起点） | [0,40] | [30,70]，完整40 | **30mm** | **70mm** | 共同10mm就在30～40 |
| 向右展开中（位移`d`） | [0,40] | [30+d,70+d]，始终完整40 | **30+d** | **70+d** | 左外缘随鼠标移动；同时用虚线标记原`x=30` |
| 刚好相邻（终点`d=10`） | [0,40] | [40,80]，完整40 | **40mm** | **80mm** | 左端从30走到40，走了**10mm**；整体从70变80，增加**10mm** |

在拖动终点只保留一条清楚的推理：

> “两环各40，刚好相邻合起来80；相扣时只有70。**80－70＝10**，是原来同一处接头里被重复计算的长度。”

支持“推回相扣”反向操作：80→70，左端40→30；来回重复不用重置全课。**同时显示第二环左端的原位虚线、当前位置竖线和一支水平的位移箭头`10mm`**，这是家长特别强调的视觉中心。用户可以按`拉开比较`按钮，也能直接鼠标拖动；两者同等效果，包含吸附终点、撤销及键盘左右方向微调。

**物理与数学边界（避免新的误导）：**真实闭合链环相扣后**不能通过简单直线滑移就完全脱开**。这里是为了看清“长度重复算在哪里”而做的**轴向长度展开比较／假想拆开再平放**，不是链环真正可实现的滑脱动作。实现建议是：保留“相扣时”的淡色原位轮廓作为参照，让可拖动的第二环**作为对比示意层/虚拟副本**从30移动到40；当它离开相扣状态，切换为“长度展开比较”的示意画法，**不能还绘制相扣的前后遮挡并暗示金属穿透/分离**。提示一句“这是把长度展开来比较，不是把真正的闭合铁环拉脱”；切勿用长篇物理说明挤占主画面。

**特别注意：**拖动到中间位置时共享区间暂时为`10-d`，但原始“两个5mm金属端部”只标在**真实相扣的`d=0`放大镜**里；不要随着拖动把原先的两个5mm错误显示为正在变化的金属厚度。拉开后的画面应强调**原来多算的10mm、移动了多少、现在的端点**。在`d=10`时只说明“轴向区间不重叠”，不再说“还有两个5mm重叠”。

### 2.5.3 界面布局只保留一个主对象，减少认知负担

宽屏（例如1440×900）建议固定为：

```text

│       环①完整40mm      环②完整40mm              │

│          └─橙色接头10mm─┘  可点开「5+5」          │
│  0           30   40                     70 mm │
│                 ▲ 原链右端   └─绿色新增30──→    │
│                                                   │
│ [逐个新增]  [拉开比较]   [复位/推回相扣]          │
│                                                   │
│ 【只问一件事】第二环也是40，为何只多30？        │
└───────────────────────────────────────────────────┘
```

上图是**标注项目示意**，不是最终严格几何图；具体横轴以`0/30/40/70`为准，不能让装饰字符的位置替代SVG测量。

- 两个模式是同一`TwoRingWorkbench`的**观察方式切换**，不是两套互不对应的卡片；同一套轴向长度坐标、同一套可追踪的环①和环②。
- **默认不要同时堆满**两种算法、5张完整长度卡、长段“投影模型”说明、下方重复放大图。每个模式只突出一个动作和一道问题。
- 接头放大镜仍使用现有“先猜一猜”里较清楚的方案，但连接到当前主图的接头框；**两个5mm应归属于两个环本身**，颜色跟主环一致，点击后才展开细节（在视角A可以默认打开，若遮挡太多则折叠）。
- 初次显示先让Kevin观察，**独立猜测环节不能预先显露`70`或`80-70=10`作为答案**；教学模式走完所需演示后再解锁结果层。现有首答与三项自查照旧，不新增强制表单。

### 2.5.4 必须先得到认可的“两环四点”样板，不得偷跑四环

Codex先交付**这两种视角的可视静态状态和最小交互样板**：

- 图A：只有一个环，40标注清晰；
- 图B：接上第二个环，**四个量同图**：第1个40、第2个40、共享10（两端5+5）、净增30；
- 图C：相扣70状态，拖动前第二环左端30mm与共同10mm；
- 图D：假想拉开相邻80状态，**左端由30移到40**、位移10mm、总长由70变80，第二个环完整外长始终40mm；

## 五、逆向题如何画：隐藏未知量，不泄露答案

当前`chainInverse`已有厚度、单环外长、环数三类求解，保留它，不重造题库。只需把逆向图和提示按同一几何关系呈现：

- **反求厚度**：已知4环、单环外长50mm、链总长176mm。先算完整外长和`4×50=200`，总共重复`200−176=24`，分给3处接头得`8`，一处包含两段等厚端部，故`t=4mm`；代回`4×50−2×4×3=176`。在儿童独立图上：接头的两段均标`?mm`，**不绘出比例恰能量得4的尺寸**，不把t预传给答案组件。
- **反求单环外长**：已知6环、厚4mm、总长140mm。每处接头`8`，5处总共`40`；完整外长合计`140+40=180`；`L=180÷6=30mm`；验`6×30−8×5=140`。图上单环外长应显示`?`、总长140，不以像素尺寸泄漏30。
- **反求环数**：先扣掉第一个完整外长，再按`L−2t`数每个新增段，最后补回1环；必须要求合理整数环数。
- 三种题的答案需遵守`L>2t`、环数限制和单位一致性；生成数值以题库实际契约为准。首次示范可以显式分步，正式独立练习不得提前显示未知值或逆推步骤。
