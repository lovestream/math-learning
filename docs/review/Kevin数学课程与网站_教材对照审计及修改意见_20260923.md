## 三、按照你提出的例子：混合运算章节应如何重排

**教材锚点：所上传三年级上册目录 PDF 第6页将“混合运算”列为第二单元、印刷第6页开始；课程稿 G3-U02 对应教材印刷6–19页。**四年级下册目录 PDF 第6页另有“四则运算”（印刷第2页）和“运算律”（印刷第17页），所以三年级的具体变形与四年级的一般化不是两套完全独立的内容。

### B 层：先完整形成教材基础（不提前硬塞奥数）

1. **B01 同级顺序**：无括号连续加减、连续乘除从左到右。`24÷6×2=8`，不把 `6×2` 擅自合成除数。先记录每步值，再去掉中间步骤。
2. **B02 不同级顺序**：无括号先乘除后加减，同时明确“乘与除彼此同级、加与减彼此同级”；练习口算中容易漏第二步的情况。
3. **B03 括号先算**：`(12+8)÷4` 与 `12+8÷4`，用物品“先合并再分组”的可见操作区分。明确此处“加括号可以改变原算式的值”，并不承诺保持数值。
4. **B04–B05 从情境构造式子**：同一购物、分组或剩余情境尝试分步算式与综合算式；每次指出括号包住的是“哪一个整体量”。
5. **基础通关**：不提示顺序的3–5道代表题，至少一题独立解释运算次序，一题从文字正确列式，一题用逆过程验算。不能只凭点击“下一页”。

### E 层：由基础自然延伸的提升

1. **E1 解释等值改写**：`60−(14+6)=60−14−6`、`60−(14−6)=60−14+6`。用“扣款/退款”或可拖拽余额条表现扣除净数量；限定适合该年龄的数域，避免把“减号后全部变号”直接作为无条件口令。
2. **E2 添括号但保持值**：`60−14+6=60−(14−6)`；与“任意加括号改变求值顺序”并排比较。需显示原式与目标式的每一步数量为何一致，而不是只比较最终答案。
3. **E3 乘除的整体问题**：对比 `48÷6÷2=4`、`48÷(6×2)=4`、`48÷(6÷2)=16`，让 Kevin 真正看见“连续除法、除以一个积、除以一个商”不是同一回事。提防 `a÷b×c` 被读成 `a÷(b×c)`。
4. **E4 运算律先操作再命名**：交换律、结合律用分组/阵列；分配律用矩形分割 `7×(5+3)=7×5+7×3`。只在图形与数量关系真正对应时使用交互，不要把乘法分配律错误套到除法或一般减法上。
5. **E5 适用边界反例**：`20−(8−3)` 与 `20−8−3` 不等；`48÷(6÷2)` 与 `48÷6÷2` 不等。每条规则都要有一条“什么时候不能这样改”的反例。

### O 层：作为可选的方法专题

- **逆向推理**：先按一个明确错误执行顺序得到结果，再逐步撤销操作找原数。
- **整体思想**：把 `a+b` 作为一个暂时不拆开的整体，随后与天平、未知数和代入连接。
- **不变量与等值改写**：哪些改变了“算式样子”却没改变“值”；哪些添括号实际上变成另一个问题。
- 注意：三上完成 E 并不要求立刻掌握四下全部字母通式和高阶奥数；四下运算律再把三上的具体实例系统化。

### 必须真正做出来的“括号实验室”交互

初始显示 `20−(8−3)` 与20个可拖拽代币。Kevin先从8个“拟扣除”代币中退回3个，再从20中扣净5个，显示结果15；切换“先扣8、再扣3”得到9，系统要求解释两个操作不同之处。随后展示 `20−8+3=15`，再让他在无代币的纸笔式里独立改写 `30−(12−4)`。应有“改变顺序”与“保持值不变”两个显式不同按钮，避免混淆。

## 七、网站方面尚未达到预期的具体缺口

- **教案→可交互课**：现有 `model` 字段只是文字，缺可执行教具事件与状态。先定义一课的交互状态机再批量迁移。验收：孩子完成操作以后，能够在不看刚才动画的情况下解释等式。
- **题库→可判断任务**：文本答案和理由不能自动转为可接受答案集合；数学等价、单位、开放解释题、图形题须有单独判题策略与人工确认出口。
- **错误→教学修复**：从“错题归章节”升级到“记录可观察错误→区分性补问→确定回补节点→新结构同类题→间隔复测”；避免一次错误推断心理或能力。
- **审阅页面的美感**：本次上传的是设计说明与教案，**没有提供当前运行网页的可视截图或可运行项目**，故不能宣称验证了现有界面的视觉品质、响应性能或交互手感。设计稿“连续阅读课堂、教具紧贴相关句子、宠物不遮挡文本”的目标合理，但必须用三年级实际课截图与 Kevin 实测验收。
- **系统状态真伪**：设计稿自己记载旧课积分规则与新课不一致、新课程未接入、四维掌握度未完成；这些是待实现事项，不能在对外产品介绍中写为已完成。

## 八、交给 Codex 的按阶段修改任务（建议直接作为执行顺序）

**阶段A：先修设计（不编码）** 产出三至六年级按“教材册→原单元→B→E→O/R”课程目录；每课来源、印刷页/PDF页、conceptId、首次/复习/深化/迁移、先修、必要或选学、交互方式。把三上 U02、四下 L01/L03 作为同一条纵向概念链详细设计。列出所有“所供混版教材必要桥接”及诊断题。

**阶段B：内容审计** 为每题增加题目 ID 与审计状态 `unreviewed / auto_checked / human_checked / needs_revision`；检查答案、单位、所有可行解、无图是否独立可做、条件边界、解释与目标一致。明确记录未查题，不能只汇报604条解析检查。

**阶段C：交互规格** 先制作混合运算五课的逐屏故事板和交互状态机；具体包含初始条件、拖拽或点击事件、公式变化、错误分支、提示撤除、独立练习与家长可见证据。确认后编码1–2节真实课给 Kevin 试学。

**阶段D：试学反馈** 每课采集：是否理解题意、独立解释是否成立、是否会在无提示的不同情境中迁移、是否主动检查，以及所需帮助层级。不只看做题分数；根据结果缩短讲解或降低E/O密度。

**阶段E：逐册实现与回归测试** 单元小批次上线；旧/新课程概念和积分只保留一个真实口径；发布任务版本稳定、迁移可回退；每批对数学、交互、存档/导入导出、复习定时和积分去重做回归测试。

## 九、最终验收标准

- Kevin 可沿自己使用的课本进入对应单元，先完成基础，随后自由进入提升/奥数，不会被高难度选学课锁住正常课本学习。
- 三上混合运算从“按顺序算”自然走到“什么时候添括号改变题意”“怎样等值添去括号”“为什么运算律成立”，三层内容在操作、题目及家长页都清楚区分。
- 每节课至少有3–5道可独立作答的匹配题；不是只换数字的所谓迁移。高难课可以拆多次。
- Kevin 能从实体或图形过渡到不依赖图的符号解释，且能说出至少一个规则不可乱用的反例。
- 新课程真正接入网站后才宣称已实现；积分、复习、掌握度和可导出存档都经实际功能测试。
- 全量教案核验给出明确的“已核验/待核验/需修订”数量，并留存可复现的测试和人工审阅记录。

**结论**：保留 CodeX 现有“教材单元→B/E/O/R”整体结构；目前最需要修改的不是再扩增课程数量，而是把**教材锚定、括号三种任务边界、跨年级概念复用、真正可操作的教具、逐题可核验性和 Kevin 试学**做实。以上项目达标后，再从三上混合运算向三至六年级扩展。
