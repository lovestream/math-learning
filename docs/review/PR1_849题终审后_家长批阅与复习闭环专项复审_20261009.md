## 二、P1：正式解释题的家长批准可能没有推进“到期复习”状态（需专项复现）

### 可定位的源码链

- \`server/pilot-store.mjs\` 的 \`submitTask()\`：
  - 自动判分正确且全部完成时，若属于到期review，会调用 \`finishReview(st.review[s.lessonId], ...)\`；
  - 这一步写入复习历史、调整stage/dueAt，并保证同一天不重复记新的独立复习证据。
- 同文件 \`reviewFormalTask()\`：家长批准解释题后设置 \`r.status = correct\`，全组均正确时设置 \`s.completedAt\` 和 \`st.review[s.lessonId] ??= {stage:0,dueAt:...}\`，但**未调用 \`finishReview()\` 或 \`prepareReview()\`**。
- \`server/review-schedule.mjs\` 的 \`finishReview()\` 恰好负责复习阶段推进、历史日期去重与下次到期日期；所以单设 \`completedAt\` 不能替代它。
- \`tests/thinking-review.test.mjs\` 测的是**17张独立思维卡**的家长审核时序；不能直接替代正式练习解释题的 \`reviewFormalTask()\` 端到端测试。
- 源码也没有在正式家长批阅时进入 \`submitTask\` 的核心组完成分支，因此“核心组完成后额外5分”的行为不一定一致。项目已有“人工批阅不直接发积分”的政策，**是否将每日核心完成奖励与逐题积分区分开是产品规则决策，不能擅自补发**。

### 为什么需要修

正式849题中含335道开放解释题，部分位于核心及到期复习组，因此家长批阅后复习阶段没有推进、重复显示已到期、第一次掌握日期不齐等现象**具备真实触发条件**。这尚未通过我独立运行代码验证界面表现，不能声称已经造成Kevin数据错误。

### 下一轮Codex最小复现（独立临时库）

1. 找一个 \`setName:'review'\` 且包含 \`explanation\` 的真实三年级课程；创建\`firstLearnedAt\`和\`review.dueAt\`已到期的合成学习记录。
2. 保存首答→三项自查→提交终答进入 \`pendingReview\`；本次同组其他题全部正确。
3. 调用 \`reviewFormalTask(...,verdict:'correct')\`；断言：课程完成状态为正确；**复习history新增本次有效日期，stage/dueAt按现有1/3/7/21规则推进**；同一天重复批阅不添加第二次独立成功。
4. 复现家长判为 \`needs-remediation\` 的路径：标为未掌握，有合适的回补/再次复习日期，不能永久滞留同一到期时间；保留首答、更正历史。
5. 复现核心\`setName:'core'\`含解释题的课程：最后一题由家长批准时，\`prepareReview\` 写入可信的初学日期/天数；与自动判分核心组的到期规划语义一致。
6. 额外核实完成奖励：**同一天已领完5分不可重复，家长批准不应发放逐题积分；是否允许核心完成奖励须写成清晰的固定规则并加测试**。
7. 多标签并发、版本升级和导入旧存档后，不丢首答、批阅历史、复习历史、积分幂等；出现冲突按既有409机制处理。

**修复边界：只改正式练习家长批阅与复习调度的最小必要代码和单元/浏览器专项测试；绝不更改已经审核的849题内容、70课UI、正式taskId、原已得积分或真实数据。**

如上述专项复现证明行为已正确，则把本条结论更新为“已验证无问题”，不再为了形式改代码。

## 三、P2：终审“335道可接受的不同表述”证据口径要更准确

- \`scripts/build-final-task-review.mjs\` 对\`explanation\`题设置：
  \`acceptableAlternative: review[i]\`；这里的\`review[i]\`是Codex逐题书写的**数学关系审校理由**，不保证它真的是“儿童可以直接写作答案的另一种自然表达”。
- \`choiceChecks[].mathematicalBasis\`对同一道选择题的每个选项也共用同一个\`review[i]\`；可能已经涉及多个选项，但不是逐选项单独的数学反证。
- \`tests/final-task-review.test.mjs\`的“335种解释替代表达”测试仅要求将该字符串交给 \`validateTask\` 时返回\`pendingReview\`。而\`shared/pilot-math.mjs\`针对解释题的规则本就是“文字至少2个字即pendingReview”，**测试无法证明替代表述数学正确**。

因此建议：
- 审计报告中的“335道都有另一种可接受表述”更名为“335道均有逐题语义审阅理由，支持家长判断多种表达”；
- 如果未来要展示孩子可用的另一种标准表达，再单独维护\`acceptableAnswerExamples[]\`并人工/代理校审，不应直接拿审核理由充答案；
- **此项只影响审计严谨性，不是目前儿童端自动评分缺陷，因为解释题本来都进入家长审核。可放到V1.0文档整理，不阻止使用。**

## 四、P2：家长批阅工作量需要在真实使用中观察

- 849题中335道解释题，占题库较大比例，系统正确地不自动给解释题判“正确”或发分。
- \`src/thinking/ParentFormalReview.tsx\` 当前每条批阅要求填写至少2字评论，并手动选正确或需要回补。对初期少量试学合理，对大量日常练习可能形成家长队列积压。
- 现阶段不应贸然给解释题自动发正确分、不应绕过家长审批；建议仅新增后台统计“待批阅数量/最久等待天数/核心与复习的待批数量”，等Kevin真实使用后再决定是否需要模板化家长评语或批量审批。这属于后续可用性优化，不是交付阻断。
