## 0. 先给决定：保留现在的六步框架，下一轮做「逐课教学品质」而不是继续批量换模板

当前整改已达到用户直接提出的**形式和流程需求**：

- 70个入口都有六步短课堂；65课追加教案，原五课沿用既有短课堂。
- 六步：真实问题 → 先猜一猜 → 亲手实验（或静态课「画图想一想」）→ 说出发现 → 写成数学 → 自己验证。
- 保留64个真实操作入口、6节静态关系图；不把静态图说成拖拽交互。
- 有图的59课在故事与猜想阶段均渲染题目条件图。
- 正式练习自查改为三项勾选、无必填自由文本；首答/最终答案/更正/积分和兼容旧记录的逻辑仍存在。
- 11课的五题「撤教具」小测沿用既有题ID，不创造重复积分。
- 提交说明中的135项测试、16组浏览器验收与CI通过，在仓库归档和GitHub Actions中有对应记录。

但是，**六步页面覆盖率≠六步数学教学质量覆盖率**。现在最重要的风险，是把「第一课的外观和步骤」误当成「第一课的视觉理解效果」。第一课有立体盒子、明显的观察位置变化和结果；某些后续课程只用小图标和文字陈述关系。下一轮建议严格围绕：故事与图片对应 → 孩子能做出数学动作 → 预测与观察可比 → 得到的数量/结构能解释 → 符号和实际模型对应 → 用新题独立验证。

**不建议再次改写所有70课的通用结构，不建议新增大量内容，不建议同时动四至六年级，也不要为了优化自查而重新增加输入框。**

## 2. 重点整改 A01：70课必须有「数学内容一致性」而不是仅有「六屏」

### 源码核对

- **content/pilot/classrooms.mjs**：65个条目各自产生 predictQuestion、predictionOptions、mission、symbols。
- **classroomFor(lesson)**：读取原课 articleBlocks[0] 作为 story，优先用 conceptScenes[0].expectedExplanation、lengthScenes[0].explanation 或 why 作为 discovery；复述优先 lesson.retellPrompt，缺省退到 mission。
- **src/studio/ChildClassroom.tsx**：所有六屏由同一模板渲染，第3屏使用原 widget，第5屏使用 authored symbols。
- **scripts/verify-template-browser.js**：逐课点开六屏、检查基本DOM、部分宽度、猜想是否保存，但并不验证符号或图片与每次实验数学状态的语义正确性。

这不是说已有70课有明确数学错误，而是**现有覆盖率测试无法排除这些错误**，需要逐课内容审核。

### Codex 要做

新增 **docs/review/三年级70课_六步教学语义台账.md**（或JSON+生成的MD），一课一行，至少有：

1. lessonId、教材章节、B/E/O/R；
2. 真实问题：对象/单位/已知量/未知量；
3. 猜想：孩子究竟要预判哪一种变化；
4. 条件图：每个数字、对象和标签是否与故事一致；
5. 操作：孩子可以改变哪个数学状态；
6. 可观察变化与不变量；
7. 「说出发现」要回答什么因果问题；
8. 数学表达：对应原故事还是当前变量；
9. 六屏后实际进入的题组，和故事是否同题；
10. 自动校验、人工截图审核、Kevin实测分别标状态。

状态建议：待核验 → 数学核验通过 → 视觉核验通过 → 亲子试学通过。**禁止只依据「六步可点开」把最后两项自动置为通过**。

至少人工精查17章各1课，并覆盖全部11课撤教具小测；剩余课先自动批量生成待审核台账。关键关系建议用确定性算式计算 oracle，不要靠对题目中文描述的正则抓数字。

## 3. 重点整改 A02：第一课的成功来自大幅图+空间关系，不只是6步

### 已观察到的截图差异

- **G3-U01-B01**：三面标记盒子、摄影机位置与箭头，图占了充足高度；一眼能看到观察对象、视角和因果关系。
- **G3-U02-B03**：12颗红珠+8颗蓝珠在手机截图里是小点，嵌在较小条件图中；孩子需要读较多文字才能理解下一步「合并再平均分装」。
- **G3-U04-B03**：8个箱子画出来，箱面均标147，但「个位满十换十、十位满十换百」这一核心关系在首屏尚未显现；实验环节需要承担这部分解释。
- **G3-U03-E02**：连接环、3处接头有画面，但应明确「每个接头占去两段金属厚度」，否则只是看见接头而不理解为什么需要减两次。

上述是**截图可见性的观察**，不是认定后面这些课程的第3屏教具失效。

### Codex 要做

对三年级选取至少17章各1课，建立移动端首屏质量检验：

- 关键数学对象在手机屏幕上可一眼辨认：不是画面过小靠文字补足；
- **图、数量、单位、题目问号**各有明确位置；图中不得提前泄露需要Kevin猜/求的答案；
- 首屏的图服务于猜想，第3屏的实验服务于验证，避免重复放两张只换颜色的「装饰图」；
- 图中的数字有明确数学语义，例如8个箱子是8组，147是每组147瓶，而不是8个小框代表8瓶；
- 对几何、质量、分数、图形变换、面积、数轴，优先用真实结构，不以大段中文说明代替；
- 禁止为了「与第一课一样大」而将长图强制拉伸失真。

对上述四课添加截图对照：390、768、1440；首屏、猜想、实验关键状态各一张。追加可访问的图形替代文本及屏幕阅读器检查。

## 4. 重点整改 A03：第5屏固定算式 vs 第3屏动态操作

**当前已做对的一点**：ChildClassroom 第5屏明确写着「下面对应第一步的故事。实验换过条件？再照这个方法写出你那一题的关系。」这避免了把固定示例冒充动态数学计算。

**仍有优化空间**：当Kevin在实验中真正切换数字、分组、角度、物体位置后，直接进入第5屏，很容易看到原故事的算式而忽略当前自己操作的状态。孩子可能不明白两者不是一组数据。

### 推荐渐进方案

- 第5屏一律明确显示「原故事的数学表达」，保留已审核的原式。
- 如果实验有**可信的结构化当前状态**且发生了变化，再显示一个独立区域：
  **「刚才我做的实验」：已知数量、问号与空白算式模板**，让Kevin口头填或纸笔写；**默认不自动给答案**。
- 如果某种教具没有结构化状态/没有数学表达生成器，就不伪造动态算式，只显示「你改了哪些条件？和原故事还一样吗？」。
- 严禁再从故事文字中抽数字构建新状态；严禁自动将当前实验运行结果直接渲染成独立验证题的答案。
- 非数值实验（观察视角、对称、角、统计分类）可以用**位置关系、条件和不变量**代替硬凑算式。

### 验收

以以下课逐一检查：

- G3-U02-B03：12+8平均装盒；原题(12+8)÷4，改分装每盒数后不能仍称「当前算式」为原式；
- G3-U04-B03：进位时位置变化与总量守恒；
- G3-U06-B03：同一整体的2/8+3/8；整体改变以后不可复用旧部分的实际数量；
- G3-UP01-B02：同船同水线条件，不给虚构的质量数值；
- G3-U01-B01：视角变化不需要强行生成等式。

## 5. 重点整改 A04：预测与实验的联系要更紧，不增加新的强制填写

当前第2屏可以点选或口述，保存了prediction；第3屏展示「刚才我的猜想」，第4屏允许打开discovery；**但没有为65课逐一设计「我原来以为X，实际观察到Y，差别为什么出现」的专门引导**。

此外，部分课的retell来自原 lesson.retellPrompt 或 fallback到 mission，可能成为重复提问而非原因解释。这是代码路径可确认的**设计风险**，不是每一课已经失败的证据。

### Codex 要做

- 每课在内容层增加字段：predictionFocus、observedEvidence、whyQuestion、counterexamplePrompt（视课可为空）。
- 第4屏只呈现**1个关键因果追问 + 1句可口头说的引导**，可以根据第2屏选项适度反馈：
  「你刚才选了……；观察一下……是否相同？为什么？」
- 允许Kevin先口头说，不增加必填框、第四个勾选、复杂评价表。
- 可以展开现有「回看关系」，但**展开只作为帮助显示，不等于独立解释已通过**。
- 对错误猜想不立即责备或直接给答案；用一个具体反例或可重复操作帮助发现。
- E/O类课程应问「为什么这个方法仍成立/何时不成立」，不能直接复用B课的普通事实回忆。

### 样板课的追问（先手工做，再推广）

| 课 | 建议口头追问 |
|---|---|
| G3-U01-B01 | 盒子没变，为什么相机从右边换到前面，能看到的图案变了？ |
| G3-U02-B03 | 如果只算12颗红珠能装几盒，为什么还不能回答总盒数？先合并再分、红蓝分别分，在这个例子中为什么结果相同？ |
| G3-U04-B03 | 10个十换1个百后，究竟变了什么？为什么瓶子总量没有变？ |
| G3-U06-B03 | 2/8加3/8，为什么要加的是份数而不是改变每份大小？ |
| G3-UP01-B02 | 为什么「同一艘船、同一水线」能代表重量相等？哪些条件必须保持？ |
| G3-U03-E02 | 每新增一个连接环，为什么会出现一个新接头而不是两个？ |

## 6. 重点整改 A05：最后一屏减轻阅读负担，避免泄露与重复

在 **ChildClassroom.tsx screen===5**，当前先渲染verification所有题干，再让孩子点击进入真正的Practice。

这可以让家长预览题组，但在儿童短课堂中可能出现：

- 先把3～5道题全部看一遍，再进Practice重新读一遍；
- 长题目在手机形成长列表，不像第一课的单动作短屏；
- 如果某一道练习和前面的完整示例数字、情境完全相同，却叫「独立验证」，容易混淆**巩固熟题**与**新情境独立迁移**。

### 修改建议

- 第6屏儿童默认只显示**题组目标、题数、一个核心检查重点和一个大按钮**，不先堆积所有题干；
- 家长模式/展开项可看题目清单与题号，方便审计；
- 对11节特殊课保留「收起教具，做五题」；
- 其他课明确是「这节课的巩固练习」，并区分后续transfer和到期review；
- 不改变既有正式Task ID、原题、答题权益/积分；
- 如果想把该步骤提升为未见迁移，需要换同结构但不同参数或情境的题，并**审定后**才计入真正独立证据，不能让原示例的原题自动算作未见题。

## 7. 重点整改 A06：三项自查已经按用户意见完成，下一步是「少打扰、真检查」

**已确认**：

- Practice.tsx 当前只需：
  1. 我读清了题目问什么；
  2. 我检查了计算或理由；
  3. 我核对了最后的答案。
- 正式流程：填写首答 → 保存首答 → 允许改答案 → 勾3项 → 提交最终答案；
- 服务端 evidenceCheck 识别 format=checklist-v1，反思文本可以为空，旧式带文字证据继续兼容；
- 正确性判分来自正式题，不来自3个勾选；不会凭勾选白送积分。

**不要倒退到过去**：不增加自查文字填写框，不对混合运算要求必填「先算了什么/中间结果」，不因用户要简化而删除首答/终答/提示记录。

### 建议先观察，再小步优化

当前每道题依然需要先保存、勾3次、提交；对连续五题会存在点击疲劳的可能。应优先收集5～10次真实操作，记录：

- 5道题中有几次真正回看题干/重新计算，有几次不看题快速勾完；
- 首答自查后主动改正了几次、是否能说清检查过什么；
- 界面是否需要自动聚焦、键盘切换、按钮间距/字体改进；
- 如果确有机械勾选，再评估「简单口算轻量检查、思维题完整三项」或「同组一次反思」**作为独立实验方案**。任何变更须先明确怎么保持逐题独立证据、后向兼容与家长批阅，不能擅自默认批量替孩子勾选。

### 必测反例

- 首答错误，勾完三项但未更正：仍应判错，不发答对分；
- 首答错误，自己更正：保留第一次错误、最终正确及selfCorrection=true；
- 使用提示再做对：assisted状态保留；
- 网络断开后填完三个勾，返回：不能丢失首答/草稿；
- 同一题重复完成：不重复发积分；
- 旧版本含文字自查记录：导入后保留原有证据，不伪造新格式。

## 8. 重点整改 A07：质量门槛要从「界面存在」升级到「数学教学正确」

现有 verify-template-browser 对70课主要验证：能打开、六个按钮、选项、第一步故事图存在、文字长度未溢出、符号行数、最后一步题数和导航恢复。这里的自动覆盖是有价值的，但**还不能保证图中尺寸、数量关系和推理过程正确**。

下一轮新增以下层级：

### 8.1 数学语义检查（机器）

- 对定量课程，结构化参数、条件图、试验状态、数学表达、核心题答案使用同一个数学oracle；若不能共享，显式标示哪个是独立例子；
