### [明确遗漏 / P2] WIRE-CASE：铁丝案例题意已提供，不能继续写“缺原题”

**位置**：`content/detective/seed-cases.mjs` 中 `DET-G3-PENDING-015`。

**已确认事实**：原对话已给出完整题意：「一根铁丝绕竹竿3圈后多3分米，绕4圈还差2分米，铁丝长多少分米？」正确列式是 `3L+3 = 4L-2`，故一圈 `L=5分米`、铁丝 `18分米`。已知孩子给出结果17分米，但**没有完整的原始中间步骤**，不能把推测的错算过程写成孩子事实。

**要求**：
1. 把「原题缺失」修订为「题意已完整；缺孩子原始计算过程」。补完整的匿名模拟找错案：例如模拟步骤先算一圈5分米，再错误地写成 `3×5+2=17`；必须标识为**虚构模拟做法**。
2. 另做不同参数/生活情境的迁移错案与正确对照案，保持2错1对的混合机制；核对两种独立关系（绕3圈多出的量、绕4圈差的量）。
3. 现有五类自动模板尚不含此类关系建模。**禁止**把不支持的题强行伪装为已有模板自动过审；优先扩充可靠的确定性模板及单元测试，否则保留待家长核对的明确状态。
4. 未重新核验及发布前，不得将旧草稿直接对儿童开放。

**验收**：完整题干、明确模拟步骤、首错、18分米正确解、两路逆查及一组新参数案例全部审定；报告指出哪些自动发布、哪些仍待核对。

### [可重现代码路径 / P2] DUP-CARDS：今日案卷与新案列表可能重复渲染同一题

**位置**：`server/detective-store.mjs` 的 `detectiveToday()` 分别构造 `cases`（今日三案）与 `newCases`（全部最近导入案）；`src/detective/DetectivePanel.tsx` 两块分别直接渲染，没有排除重叠的 `case.version`。

**风险**：若新到案件同时入选今日计划，儿童界面会出现两张内容完全相同的卡片。当前服务端已有防重复尝试和徽章机制，**不能据此说产生了双倍奖励**；这是展示去重/认知负担问题。

**要求**：
1. 选择一种不丢失全部新案入口的UI规则：例如「新到区隐藏今日已展示案，且案卷柜/历史可找到该案」；或在一个区域展示并标记另一处入口。
2. 处理当日计划版本快照与新案当前活动版本不同的边界：按 `caseId + version` 判断，不得混淆旧作答历史。
3. 增加重叠测试：同一个进口案同时位于今日计划和新到列表，浏览器可见卡片不能重复，首答与当天徽章上限不变。

**验收**：今日3案、新到15案、已有历史均可找到且无重复可见卡；刷新、重启、跨版本仍成立。

### [长期使用风险 / P1 设计，不阻塞短期试用] LONG-RETENTION：硬容量上限需要迁移方案

**位置**：`shared/detective-model.mjs` 的 `validateDetective` 与 `server/detective-store.mjs` 的上限分支。

当前存储限制：最多**200宗案、1,000次调查、400天计划、1,000枚徽章、每案20版本、3MiB侦探数据**，同时对 `studio` 总字节有额外限制。现有策略是超限后拒绝新增，保障旧数据不被静默删除，这是正确的安全原则；但**不是长期可扩展的最终方案**。如果独立调查平均每天3次且都是新尝试，1000次约333天触顶（只是情景演算，不是预测）。

**要求**：
1. **本轮先给架构方案和数据迁移设计**，无需贸然重构全部学习系统；说明案件主数据、不可变作答事件、年度归档、索引/检索和备份恢复边界。
2. 选择可测试的增量迁移方式；保证旧数据可读、旧案卷版本和首答关联不变，家庭 NAS/将来云端部署不锁死在单一存储形式。
3. 分阶段压力测试超过200案、1000次调查、400天；允许历史安全归档与检索，但不自动丢失证据、不污染原正式课程。
4. 给出实际可扩容量、读取性能、备份体积及磁盘空间不足时处理策略。
5. **不要**只把 `1000` 改为更大的常量作为最终解决方案。

**验收**：先提交设计与迁移测试计划供确认，再执行结构性改造；避免在当前短期可用的V1上引入未经批准的大规模存储改动。

### [覆盖范围 / P2 后续阶段] MODEL-COVERAGE：空间图形及多条件应用题尚无稳定自动通道

**已确认事实**：严格自动发布目前只支持5类模板；用户上传的三年级试卷还有空间观察、正方体展开图、线段关系、行程以及多条件应用题。此限制已在现有文档承认，不是已支持的五类模板发生故障。

**要求**：
1. 建立「照片源题→人工确认提取→数学模型/检查路线→匿名模拟错误→迁移正确案」题型覆盖台账。图形题必须避免凭一张模糊图片生成唯一答案。
2. 优先按最近真实易错模式扩展2—3种**可确定性判定**模板，而非以任意中文大模型结果代替独立数学验证；开放题仍进入家长核对。
3. 不向公开 GitHub 上传孩子原试卷、笔迹、姓名、班级、老师评语或作答历史。不要在儿童前端下发未开放的标准答案。

**验收**：新模板含正误对照、首错、迁移题、逆向验证、边界例子、正常/恶意数据拒绝测试及浏览器检查；扩展计划独立于本次短期上线门槛。
