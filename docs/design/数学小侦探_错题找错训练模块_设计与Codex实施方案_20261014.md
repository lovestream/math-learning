# 2. 每日体验：5～8分钟，一次3宗案

默认每天3题（家长以后可调为2/3/5），建议安排**2宗错误案＋1宗正确案**，随机顺序，避免孩子知道“这里肯定错了”。每轮题要有跨类别变化；近期易错类优先，但不要3题全是同一答案。

## 2.1 儿童端四个短步骤（不是再强制写一遍长篇六步课）

1. **读案卷：先作判断**  
   屏幕同时显示清楚的原题、某位虚构同学的做法/列式/排序/草图，以及一个易辨识的数学条件图。选「有问题」或「没问题」。必要时可以选「条件不够」，但V1普通案件只发布对错能确定的题。
2. **找证据：圈出第一处可证明的问题**  
   若判“有问题”，点/圈错的步骤、符号、单位、顺序或估计值，再选最贴切的理由。若判“没问题”，指出核对依据，而不是随便点“对”。错因可为“题目要求看反了”“没统一单位”“少算一步”“数位换错了”等，**不能靠选项措辞泄露正确答案**。
3. **修复案情：改成正确的**  
   数值题输入答案或拖动步骤卡改错；方向排序题可拖动排序；图形/度量题尽量调用现有尺子、位值、分数、天平或积木可视模型。先保留独立首答，反馈后允许修改，不要在这一步直接展示完整标准答案。
4. **复核结案：换一种检查方式**  
   默认使用**与原做法不同的验证动作**：统一单位、用逆运算、估算数量级、带入、换视角、画尺/数线、逐项核对条件。短口头提示即可，不强迫Kevin每案输入大段说明；用1个简短选项/填空记录“我用了什么证据”。最后显示原因和完整正确过程，再给勋章/分数，学习未独立完成的状态要如实保留。

### 2.2 关键交互行为

- 第一判断**提交后封存**，不能因为最终修好了就改写第一次“错误/正确”的记录。
- 误报（题本来正确却判有错）与漏报（题有错却判没错）都要有不同反馈。
- 可以“给一点线索”，分层提示先提醒审题条件、再提示核对方法、最后展示关键一步；提示之后纠正成功只记“辅助破案”。
- 正确案不能强迫选择“错误步骤”；应通过不同的检查路线结案。
- 允许说出原因给爸爸听，不依赖浏览器录音/语音识别、AI自动主观判分。
- 学生界面严禁提前收到标准答案、正确步骤定位、家长审核备注；答案判定在服务端。
- 打开原作业的实际错题，仅在**家长管理页面**显示“来自Kevin某次作业”，儿童端都使用“侦探案卷”的虚构角色表达，减少自我标签和挫败感。
- 对判断正确但没法说出原因的情况，显示“发现线索，仍需核实”，不要当作“独立会检查”。

# 3. 为什么这不同于“重做错题”

**需要真实地训练五种可观察能力**：

| 能力 | 典型缺陷 | 调查动作 | 验证动作 |
|---|---|---|---|
| 审题 | “从长到短”看成“从短到长” | 先圈“从长到短”，再判断顺序 | 逐个换同单位，再比首尾 |
| 数感与现实估计 | 香蕉大约2厘米 | 用手指/尺子的实际尺度比较 | 估算量级，不要求香蕉固定唯一标准长度 |
| 单位 | 2厘米忘换为20毫米；1千米写成100米 | 找单位转换在哪一步出错 | 单位等价换算+现实尺度 |
| 运算与步骤 | 运算符号看错、混合运算漏算第二步 | 在过程的某行定位**第一处错误** | 逆算、重算、分步计算 |
| 检查与证据 | 写完以后重复看一遍却发现不了 | 选择一种独立检查方法 | 用不同路线核验，而非照原过程再读一遍 |

**不要把所有错误都归成“粗心”。** 错因应是可观察行为；孩子的内在原因只是待验证假设。单次失败不能做注意力/性格标签。

# 4. 首批素材：真实错题与正确“假线索”混合

**首批发布建议：12～15宗审定案件。** 以下表格可作为内容制作输入，正确答案是本设计的数学核对结果，不代表原作业题干之外还有附加事实。发布前家长可以看预览并确认。

| 案卷ID | 儿童端题干/嫌疑做法（概述） | 判定 | 正确关系/检查重点 | 错误模式 |
|---|---|---|---|---|
| DET-G3-001 | 香蕉长约2厘米 | 有问题 | 2厘米明显不符合普通香蕉的长度尺度；用10厘米尺比较。**长度没有唯一正确数字，不强制要求某个精确答案** | 现实估计、单位量感 |
| DET-G3-002 | 要“从长到短”排：73毫米→3米8分米→54分米→9千米200米 | 有问题 | 9千米200米 ＞ 54分米 ＞ 3米8分米 ＞ 73毫米 | 读题方向、单位统一 |
| DET-G3-003 | 3张卡总厚度2毫米，求2厘米厚，小智说“2厘米=20毫米，20÷2=10组，所以只要10张” | 有问题 | 2厘米=20毫米；20÷2×3=30张 | 单位换算、数量对应 |
| DET-G3-004 | 把1千米写成100米 | 有问题 | 1千米=1000米；可以分为10组100米 | 位值/千米换算 |
| DET-G3-005 | 9÷3−2=6 | 有问题 | 9÷3=3，3−2=1 | 漏算步骤或错误合并 |
| DET-G3-006 | 9×9＋5=76 | 有问题 | 81＋5=86 | 数值计算/验算 |
| DET-G3-007 | 7×8＋18=38 | 有问题 | 56＋18=74 | 乘法事实与后续步骤 |
| DET-G3-008 | 500＋600=1010 | 有问题 | 1100；可用百位块重组 | 数位重组 |
| DET-G3-009 | 1100−300=980 | 有问题 | 800；可逆算800+300=1100 | 减法计算 |
| DET-G3-010 | 3×3=6 | 有问题 | 9；三组各3的实物阵列 | 乘法意义 |
| DET-G3-011 | “1千米=1000米”，小智说正确 | **没有问题** | 用10组100米确认 | 正确案，防误报 |
| DET-G3-012 | (12+8)÷4=5 | **没有问题** | 12+8=20，20÷4=5 | 正确案，运算顺序 |
| DET-G3-013 | 9千米200米比54分米长 | **没有问题** | 统一单位比，不凭数字位数猜 | 正确案，估量与单位 |
| DET-G3-014 | 三张卡合计2毫米，三十张厚20毫米 | **没有问题** | 30÷3×2=20毫米 | 正确案，比例 |
| DET-G3-PENDING-015 | 铁丝长度题：Kevin得到17分米，原标准答案18分米 | **待原题** | 已知“18分米”但缺完整原题和计算步骤；**不可擅自补造题目或直接发布** | 待家长补录 |

**重要校验说明**：
- D003正确的是**30张**而不是“30毫米”：20÷2=10（组三张），10×3=30张。嫌疑人算出“10组”本身没有错，**第一处错误**是把10组误当成10张；必须在儿童交互中允许先认可正确步骤、再定位那一步。
- D002的原始家长反馈是“整组顺序写反”，这里具体排列仅为**由此设计的模拟案件**，不是对Kevin当时纸面填空的逐字记录。
- D001只能判数量级明显不合理，不能把“普通香蕉一定20厘米”设计成标准答案。
- D005至D010只知道最终错误算式，**不知道Kevin当时真正的逐步思考**。儿童端展示的推理步骤需标记为“模拟学生做法”，不能假装复原Kevin实际脑内过程。
- 这14宗里4宗正确案（约29%）；生产题包可保持25%～40%正确案，视学习情况微调。
- 所有“正确案”也要设计一个真正可执行的验证方法，不能仅靠系统说“是对的”。

# 5. 家长后台：错题录入是首期最重要的能力

推荐新页面「家长中心 → 侦探案卷管理」，沿用**现有家长PIN与权限**，不得给普通儿童页面写案卷权限。

### 5.1 一分钟录入向导

**最少四个必需字段**：
1. **原题**：原样输入，单位、条件、问题完整；可换行。
2. **做错的过程**：孩子的原答案/计算步骤/排序结果。若只是答案错、不知道步骤，就记“仅有错误答案”，不可凭空造思路。
3. **正确结果和理由**：家长确认参考解法、关键条件和检查方法；开放性题可用“可接受范围/描述”。
4. **案例标签与状态**：错误类别（默认可自动建议但需确认），保存为“草稿/待审核”；家长点击发布才进儿童题库。

建议可选字段：\`grade\`、对应教材 \`unitId/lessonId\`、来源日期、班级作业/网站正式练习/家长手录、错因假设、数学模型、预计难度、可使用的线索、可接受的其他解法。

**发布前家长检查**：
- 题意是否完整，答案是数值/范围/等值式还是开放解释？
- “错误过程”真的存在可定位错误吗？第一处错误有确定的证据吗？若只是最终值不同而不能定位，改用“结果疑案”，不要制造假步骤。
- 是否唯一解？可能多种正确说法的题必须允许家长审批。
- 是否错误题和正确题兼容？家长可以主动建立“原做法没有错”案件。
- 是否含敏感身份、姓名/学号/校名？若有，制作儿童案卷时自动使用匿名字段。

### 5.2 支持三条入库路径

- **手工录题（MVP必须）**：直接复制或输入问题、错误解答、正确过程，速度最重要。
- **从网站错题选入（MVP后期可做）**：从正式练习\`attempt\`生成“草稿”，指向原attempt ID和原课程版本；要求家长重新审定正确数学关系，**不得把系统diagnostic原样当成Kevin犯错原因**。
- **作业图片辅助录题（V2）**：家长可上传/关联图片，但**不能仅凭自动OCR/AI抽取就直接发布**；需要编辑核对。原图作为私有资料，儿童端只展示审定后的题面与示意图；图片不塞进学习进度JSON或Git仓库。图片储存由可替换资产接口提供，预留长期NAS与云端方案。

### 5.3 删除、修改与回放

- 家长可保存草稿、预览、发布、撤回、归档、复制题目生成新版本；不要直接物理删除孩子已作答案件的历史证据。
- **一旦发布/有人作答，题目版本不可原地覆盖**。修改数学题意/答案必须产生新版本和内容指纹；旧答保留指向旧版本。
- 修改标签/提示文本若确实不影响评分，记录编辑版本即可；若误判影响答案，需重新审阅已完成证据和奖励，不可静默回写。

# 6. 题库抽象：题目与错误过程是两个不同对象

不要仅做 \`question + correctAnswer + wrongAnswer\` 的扁平结构。侦探要找的是**一处可证实的错误或一个已验证正确的完整过程**。

下面是建议的**示意数据契约**，不是当前项目已有接口：

\`\`\`ts
type DetectiveCase = {
  id: string;                   // 不复用正式Task ID
  version: string;              // 内容版本/指纹
  status: "draft"|"review"|"published"|"archived";
  origin: {
    kind: "parent-manual"|"existing-wrong-attempt"|"authored-seed";
    lessonId?: string;
    originalAttemptId?: string;
    capturedAt?: string;
  };
  grade: 3|4|5|6;
  unitId?: string;
  familyId: string;             // 同一错误模式，用于复习与去重
  difficulty: 1|2|3;
  prompt: string;               // 完整、家长已核对的题面
  suspect: {
    displayName: string;        // 虚构名字
    steps: Array<{id:string;text:string;math?:unknown}>;
    finalAnswer?: string;
  };
  verdict: "wrong"|"correct";
  firstWrongStepId: string|null;// 正确案必须为null；仅知错值可标final-answer
  errorTags: string[];          // 可见行为标签，不是人格标签
  reasoningEvidence: string[];  // 为什么判错/判对的明确依据
  repairedSteps?: Array<{id:string;text:string}>;
  expectedResponse: {
    kind:"number"|"expression"|"choice"|"ordering"|"explanation"|"plausibility";
    numeric?: string;
    accepted?: string[];
    rubric?: string[];
  };
  checkMethod: "units"|"inverse"|"recompute"|"estimate"|
               "substitute"|"diagram"|"condition-check"|"order-check";
  visual?: {type:string;props:Record<string,unknown>};
  hints: string[];
  sourceNotes?: string;         // 私有；不得发给儿童API
  editorialRevision: string;
  contentHash: string;
};
\`\`\`

建议拆分为：
- \`case\`：案卷题面、正确/错误做法、数学关系、家长发布状态；
- \`attempt\`：孩子哪一次调查、第一次判断、指出步骤、修改、提示、最后检查；
- \`family\`：同一易错结构；不同参数的新案可以复用检验方法；
- \`review\`：调度阶段、到期、独立还是辅助、历史；
- \`event\`：不可逆的关键证据，包括首答、提示、审核、积分回执。

数学规则必须由**结构化场景字段或服务端确定性验证器**提供，不允许靠题面里搜索“数字”和“关键词”拼凑标准答案。不确定和开放题不能强行自动判正确或错误。

## 6.1 儿童记录的精确定义

\`\`\`ts
type DetectiveAttempt = {
  attemptId: string; caseId:string; caseVersion:string;
  startedAt:string; completedAt?:string;
  firstVerdict?: "wrong"|"correct"|"insufficient"; // 首判断，后续不可覆盖
  locatedStepId?:string|null;
  chosenReason?:string;
  repairedAnswer?:unknown;
  verificationMethod?:string;
  hintsViewed: string[];
  finalVerdict?:string;
  status:"in-progress"|"closed-independent"|"closed-assisted"|
         "needs-revisit"|"parent-review";
  errorTypeDetected?:string;    // 从动作推断，不等于孩子性格
  rewardLedgerId?:string;
};
\`\`\`

**“首判正确”不等于“独立破案”**：还需定位第一错误点/说明正确依据、修复并通过独立验证；给提示后修正要记辅助。高难度题若存在多种正确检查方法，使用rubric并可转家长审核。

# 7. 错因分类和游戏生成规范

建议一级错误标签：
- \`READING_DIRECTION\` 题目方向、问什么、先后/多少；
- \`UNIT_CONVERSION\` 单位换算、计量单位；
- \`PLAUSIBILITY\` 现实尺度、合理性估计；
- \`OPERATOR\` 加减乘除符号看错；
- \`ORDER_OF_OPERATIONS\` 括号和运算顺序；
- \`PLACE_VALUE\` 数位、进退位、零占位；
- \`INCOMPLETE_STEP\` 漏做最后一步；
- \`MODEL_RELATION\` 整体/份数、倍数、等量替换；
- \`CHECKING_METHOD\` 检验方法无效或遗漏条件。

允许一个案件打多个标签，但MVP应提供一个**首要错误位置与核心核对方法**。统计聚合分清“孩子识别出的错因”与“家长审定的真因”，不要一票失败就判断注意力有问题。

### 7.1 同结构变式的设计

- 真题模拟案与迁移案用同一数学关系，但换数字/单位/具体物品/展示形式；不能只把原答案换个颜色。
- 每个\`familyId\`至少准备一题不重复的延迟复习案；不能当天给与题面完全一样的题就算迁移。
- 正确案与错误案成对设计，避免每张都有错；V1日常随机顺序，固定seed可复现。
- 所有参数变化后，**题干、错误步骤、第一错误点、解法、模型、验证方式都由同一数学状态推导或重新复核**。
- 对无法参数化的实物合理性案，优先由家长补真实尺度模型，不强行制造“唯一香蕉长度”。

# 8. 日常计划、奖励与复习安排

**建议默认**：
- 每天3宗，5～8分钟；家长可暂停和跳过；
- 每轮1宗已掌握结构的正确验证案、2宗近期或历史易错案；题数少时允许来源多样化；
- 以流程证据为目标：**发现错/没错 → 定位或给证据 → 修复 → 换方法核验**；
- 1/3/7/21天可借现有调度思想，但独立保存在侦探\`familyId\`中；原课程复习阶段不能被侦探表现擅自推进；
- 同一错误模式可选择“错误案→正确案→换情境新案”，检验是否形成合理的检查习惯；
- 重点记录误报率、漏报率、提示前修复率、独立验证成功率、隔日新情境成功率，而非只统计总正确率。

**积分/徽章方案**（需和现有钱包规则交叉检查）：
- 建议首版以侦探徽章（不兑换资源）为主要反馈；若要用已有统一积分，只有第一次真实完成有效案且记录完整才能发少量积分，比如**每案1分、每天最多3分**，加入原全局奖励上限，家长可选择关闭；
- 同案同版本反复完成、刷新、重复请求、多标签并发，均**不得重复得分**；
- 已从正式练习错题转化的案，不得因“原题答案再答一次”重复领取正式练习权益；
- **抓到自己的误判并纠正也值得肯定**，不能通过“越快点击越多分”鼓励瞎猜。
- 不直接奖励“把别人找错”而忽视检验；更不奖励家长或系统自动给的最终答案。

## 9.2 建议API（合同草案）

- \`GET /api/detective/today\`：仅公开题目和嫌疑做法，不回传答案/内部错点/私有来源。
- \`POST /api/detective/attempt\`：按\`action:first-verdict | locate | repair | verify | hint\`写入不可回写的首判/提示/最终证据，带\`eventId\`与\`expectedRevision\`；答案只在到阶段后按策略显示。
- \`GET /api/detective/history\`：儿童可查看自己的“案件历史”，不显示家长私有备注。
- \`GET /api/parent/detective/cases\`：需PIN，列表、待发布审核、错因统计、来源信息。
- \`POST /api/parent/detective/cases\`：家长创建/编辑/发布/撤回/归档，服务端白名单字段、权限、内容指纹、版本检查。
- \`POST /api/parent/detective/grade\`：家长核定开放解释或有多个合理答案的案件，保留版本与批阅证据。

HTTP方法与路径可由Codex按项目风格微调；**安全要求不可省**：学生端和原始\`/api/data\`快照不得泄露尚未调查的\`expected\`/\`firstWrongStepId\`/\`reasoningEvidence\`/\`sourceNotes\`，尤其不要将全部案件答案作为\`progress\`公开返回。

## 9.3 存储的关键设计决策

当前\`progress.sqlite\`并非大量规范化业务表，而是单行\`progress.payload\`JSON，含学习、积分、宠物、错题记录。不要直接往其中无界塞大量作业原图或数万条原始交互事件。

MVP建议：
- 经审核案件源与儿童作答历史**在服务端隔离**，案例来源备注、正确答案不得泄露给学生端；
- 存储层抽象成\`CaseRepository\` / \`DetectiveProgressRepository\`，保留可迁移接口；
- 可先在现有进度格式中增加独立\`studio.detective\`命名空间，但必须限定数据体积、版本、数量、并发安全；或者建立专用SQLite表。**无论选哪条，都必须完整纳入现有导出、导入、每日备份和恢复机制**；不能因为“存到SQLite另一个表”就导致当前备份只保存旧payload。
- 案卷主数据与侦探作答**分开存**；儿童API只给题面，家长API经授权返回答案；即便部署到NAS或未来换云端也不依赖浏览器本地私有存储作为唯一数据源。
- 服务端验证内容hash、caseVersion、字段长度、回执幂等、草稿状态、家长发布前检查；过期修改必须409拒绝。
- 不允许任何功能测试读取或覆盖Kevin真实数据库；测试在临时\`--data-dir\`运行，并验证旧备份不含侦探字段也能恢复。

# 10. Codex 分阶段实施（**控制范围，避免无限项目**）

## 阶段A（必须，做成可用V1.0）

1. 完成\`DetectiveCase\`/Attempt契约、14宗经家长审核的示例案件（10错+4对）、严格的确定性数学判定和“未核对不得发布”门槛；第15宗铁丝题保持待补录。
2. 儿童入口、每天3宗、四步交互、正确案/错误案、首判断冻结、证据/修复/换方法验证、有限提示、完成页。
3. 家长PIN后台**手工新增案件、编辑草稿、预览、发布、撤回、归档**；允许以后家长不断添加Kevin常见错题，发布审核为刚性门槛。
4. 侦探会话保存、刷新/中断恢复、导出/导入、版本/历史、重复提交幂等、不能篡改首答；学生端不能看私有答案。
5. 对现有学习地图、六步课堂、849题、思维卡和奖励逻辑只做**必要导航/复用改动**，旧测试不回退。

## 阶段B（V1.1，可在V1稳定后）

6. 从错题修复站一键生成家长草稿，关联原练习\`lessonId/taskId/contentVersion\`但不复制原积分权益。
7. 按错误类型/单位/题型投放迁移变式；独立的1/3/7/21复习、误报/漏报与长期掌握看板。
8. 按真实试用反馈，优先把排序、数位、长度、单位、图形错误的复核变成拖拽/尺子/数线交互；避免“全是文字选择题”。

## 阶段C（未来，不阻碍V1发布）

9. 作业图片上传+人工校对文字；AI/OCR可以作为建议草稿，但**必须人工批准**；原图隔离与多媒体资产管理。
10. 家长批量导入、多学年错因趋势、与英语/其他学科积分跨站统一；明确只在实际有需要时启动。

# 11. 详细验收清单（Codex须保存实际证据）

### 数学与学习行为（至少）

- [ ] 正确案：首次判断“没问题”后能给验证依据并结案；误判有问题后可以纠正，记录误报，不要求选不存在的错误行。
- [ ] 错误案：首次判断有问题后定位**第一处**错误，改正并换路核验；只写出最后答案不能冒充定位错误成功。
- [ ] 数学专项：排序应为9km200m ＞ 54dm ＞ 3m8dm ＞ 73mm；手机卡答案30张；1km=1000m；三个混合运算分别为1、86、74。
- [ ] 香蕉合理性：2cm是明显偏小的估计；不宣称“标准香蕉只能是某一个数字”。
- [ ] 铁丝17/18分米：缺原题，处于草稿，不对儿童发布，不由程序虚构题目。
- [ ] 任何提示后做对仍记\`assisted\`；独立与辅助在记录和奖励方面分开。
- [ ] 一轮题里混有至少一宗正确案；随机顺序不会固定为“第3题一定对”；同模式复习使用不同条件的新案。
- [ ] 首判保存后刷新，不能重新选择覆盖首次判断；误判/漏报历史保留。
- [ ] 家长编辑已发布案件改动数学关系，新版本不会污染旧尝试、旧判分；草稿不公开，撤回后孩子已完成历史仍可查看。
- [ ] 讲出合理的其他正确方法不被关键词机械判错；需要家长审阅的答案不会被自动判正或发奖。
- [ ] 幼儿端页面看不到后台答案、私有来源、错误步骤键值等“解析泄露”；通过真实HTTP接口测试，而不是只隐藏React DOM。

### 工程、存档与权限（至少）

- [ ] 本地电脑 Chrome 完成一套3案，支持页面返回、暂停续做、断网恢复。
- [ ] 家长PIN未解锁无法创建/发布案件；普通学生POST不能伪造家长审核；写操作保留当前同源校验。
- [ ] 完整旧版备份导入保留原70课进度、积分、宠物、正式题首答；新数据也确实参与导出/备份/恢复，checksum有意义。
- [ ] 同一次完成请求重试100次只发一次侦探奖励；没有从正式题/普通完成奖励双重领分。
- [ ] 双标签页同时编辑、旧revision提交，返回409且不覆盖新记录。
- [ ] 历史案卷数增长、测试数据运行时，存档大小与初始加载时间处于可接受范围；图片/附件不放进主学习JSON。

# 12. 不可逾越的产品边界与“何时完成”

- **不是再做第二套正式练习**：侦探首先要判断别人有没有错，再找证据、修复与验证。
- **不是让Kevin每天看到自己错误被公开展示**：真实原作业家长私有保存，儿童角色匿名。
- **不是每次再填4个反思框**：符合Kevin三年级年龄和家庭对流程简洁的要求；说明可以口述，默认不强制文字。
- **不是默认100%案件都有错**：正确案必须至少约四分之一，训练误报控制。
- **不是“没犯错就满分”**：主动发现自身错误并复核，成长证据同样重要。
- **不是启用自动AI批阅自由回答**：开放答案需审核或经过审定的结构化可判规则。
- **不是为了数学小侦探重构全部网站**：70课和849题已交付的学习记录不可破坏。
- **MVP完成定义**：家长可自己录入并发布新错题；Kevin可用电脑完成正确与错误混合的3案，真实保存首判/定位/纠错/验证；正确/辅助证据分开；旧数据安全；CI与浏览器通过。**达到此标准即可用，不必等待V1.1自动收集、变式复习或图像识别。**
